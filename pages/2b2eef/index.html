git log 常用参数：

-n：限制结果数量，只显示最近的 n 条提交记录。例如，git log -n 5 只显示最近的5个提交。

--author=author：只显示指定作者的提交记录。例如，git log --author="John Doe" 只显示作者为 “John Doe” 的提交记录。

--since 和 --until：指定日期范围，只显示在给定日期范围内的提交记录。例如，git log --since="2021-01-01" --until="2021-12-31" 只显示2021年的提交记录。

--oneline：以简洁的方式显示每个提交的摘要信息，每个提交只占一行。这可以在查看大量提交记录时提供更简洁的输出。

--graph：在输出中显示图形化的分支合并历史。这可以帮助你更清楚地了解分支之间的合并关系。

--decorate：在输出中显示分支和标签的名称。这可以帮助你更容易地识别每个提交所在的分支。

--all：显示所有分支的提交历史，而不仅仅是当前分支的历史。

//例如，插入最近十条记录，所有分支下的
git log -10 --oneline --graph --all

//查看单个文件的记录历史（**常用**）
git log filename
//查看跟踪该文件device-vext.mk ，并-p显示代码提交，其过滤这个ro.lmk.swap_free_low_percentage修改
git log -p --follow device-vext.mk | grep  ro.lmk.swap_free_low_percentage -C 20

//我们还可以将其回滚到指定的版本文件
git reset 1a1e9 min.c

//重置缓冲区的操作（常用）
git reset

# 原理必知

git中的commit显示的文件是如何管理的呢？又是如何管理commit id的呢？

可以看到，其中commit id是一个hash值，并且我们可以使用 git cat-file -p xxx，来查看这个hash值，其中有tree 和 node，一个节点就是一个文件。

本地分支和远程分支的关系？

本地分支不一定要和远程分支关联，如果要做到关联可以这样操作:

//将本地分支和远程分支关联，不然是无法推送的！
git branch --set-upstream-to master origin/master

//关联之后，新建的分支提交需要如下：
git push 

//此时我们切换回本地的其他分支，如果该分支和远程没有同步，git会提醒你，
git pull

# 将两笔提交合并为一笔

  • git branch -a：确定要合并的path以及分支
  • git rebase -i HEAD~2 ：此时会打开一个编辑器，在最上面的区域列出了最新的两个提交（~2表示合入前2笔）

如果此时你本地还存在修改，git statsu 会出现你的修改；确定不需要这些修改后，可以使用命令

git checkout – filepathname 删掉对应文件里你的修改

git checkout . 放弃所有的修改

如果需要一些修改的话，可以先删一些，然后git add . 一些，确保本地不存在未提交缓存区的修改

  • 将第二个提交的pick改为squash 或者s

    pick 7306fa6 commit message
s 1a37b3d commit message
    1
    2

  • 保存并关闭编辑器，接着会打开一个类似于合并提交的编辑器，在这里编辑合并后的提交信息。保存并关闭编辑器

  • 执行git push --force命令，将新的合并提交推送到远程仓库

执行完后会提示你提交代码：

如果你此时不在一个分支上，git branch 是这样的：* (no branch)，则需要按提示使用该命令 git push origin HEAD:<name-of-remote-branch>来提交代码到对应的分支：

如果你不想这么做，可以切换到一个分支上，使用命令git push origin 来提交代码，但是这么有点麻烦， 似乎也不麻烦：

使用命令切换分支：git checkout -b tran_mtk_u0.mp1.rc_trunk remotes/origin/tran_mtk_u0.mp1.rc_trunk 这时，会提示你将本地”被遗弃“的commit 一并带到新分支：

这里，我们已经切换到新分支，可以使用该命令挽救：

git cherry-pick xxxcommit

将”被遗弃“该笔commit，pick过来到新分支

  • 重新提交代码git push origin

最后重新提交代码即可，这里因为之前我们切换到了新分支，也可以使用命令git push origin

# gerrit网站上出现Merge Conflict

出现的原因：

我们在公司服务器上提交的代码，但是没有merge权限，其实还是没有到服务器上的，只是显示在了gerrit网站上，这个时候需要leader进行合入。但是为什么有时候上午提交的代码还没Merge Conflict 但是到了晚上就会出现呢？ 原因就是这个时候有同事在你修改的地方动了代码，并且合入了！这样，远程的代码识别出来这个位置和你的不一样，就会出现这个情况！

# 分布式和集中式

git是分布式的，但是svn、csv则是集中式的版本控制系统。他们之间的区别为：

集中式的版本控制系统每次在写代码时都需要从服务器中拉取一份下来，并且如果服务器丢失了，那么所有的就都丢失了，你本机客户端仅保存当前的版本信息，换句话说，集中式就是把代码放在一个服务器上集中管理，你的所有回滚等操作都需要服务器的支持。

分布式的区别在于，每个人的电脑都是服务器，当你从主仓库拉取一份代码下来后，你的电脑就是服务器，无需担心主仓库被删或者找不到的情况，你可以自由在本地回滚，提交，当你想把自己的代码提交到主仓库时，只需要合并推送到主仓库就可以了，同时你可以把自己的代码新建一份仓库分享给其它人。

像集中式它们都有一个主版本号，所有的版本迭代都以这个版本号为主，而分布式因为每个客户端都是服务器，git没有固定的版本号，但是有一个由哈希算法算出的id，用来回滚用的，同时也有一个master仓库，这个仓库是一切分支仓库的主仓库，我们可以推送提交到master并合并到主仓库上，主仓库的版本号会迭代一次，我们客户端上的git版本号无论迭代多少次，都跟master无关，只有合并时，master才会迭代一次。

git pull
    git pull 命令的作用是：将远程主机的内容拉下来后直接合并，即：git pull = git fetch + git merge，可能会产生冲突，需要手动解决。它的完整格式稍稍有点复杂。
 
    git pull [<options>] [<repository> [<refspec>…​]]
    git pull  <远程主机名>   <远程分支名>:<本地分支名>
        比如，要取回origin主机的next分支，与本地的master分支合并，需要写成下面这样:
    git pull origin next:master
        如果远程分支(next)要与当前分支合并，则冒号后面的部分可以省略。上面命令可以简写为：
    git pull origin next
 
        什么时候使用  git pull [远程主机名] [远程分支名] [本地分支名]  ?
        修改比较简单，确定不会产生合并冲突的时候。
 
        什么时候使用git fetch [远程主机名] [远程分子名]，git merge [远程库名/远程分支名] [本地分支]
        远程仓库的修改可能和本地仓库产生冲突的时候，可以先把远程仓库的放到本地。经过对比之类后，再进行合并（也要解决冲突）。
