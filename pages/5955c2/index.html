# spring

# 简介

Spring是分层的 Java SE/EE应用 full-stack 轻量级开源框架，以 IoC（Inverse Of Control：反转控制）和 AOP（Aspect Oriented Programming：面向切面编程）为内核。

提供了展现层 SpringMVC 和持久层 Spring JDBCTemplate 以及业务层事务管理等众多的企业级应用技术，还能整合开源世界众多著名的第三方框架和类库，逐渐成为使用最多的Java EE 企业应用开源框架。

spring的优势：

  • 方便解耦，简化开发: 通过spring提高的ioc容器，可以将对象间的依赖关系交给spring控制，我们也不必为单例模式类、属性文件解析等头疼，只需要专注于上层应用
  • aop的编程支持： 通过 Spring的 AOP 功能，方便进行面向切面编程，许多不容易用传统 OOP 实现的功能可以通过 AOP 轻松实现
  • 声明式事务的支持
  • 方便程序的测试
  • 方便继承各种优秀的框架
  • 降低javaee api的使用难度： Spring对 JavaEE API（如 JDBC、JavaMail、远程调用等）进行了薄薄的封装层，使这些 API 的使用难度大为降低
  • 值得学习：Spring的源代码设计精妙、结构清晰、匠心独用，处处体现着大师对Java 设计模式灵活运用以及对 Java技术的高深造诣

# bean组件配置

  • Bean标签的基本属性配置

    • id：Bean实例在spring容器中的唯一标识
    • class：Bean的全限定名称

  • scope属性：代表bean标签作用范围

    • singleton 默认值，单例的
      • 加载配置文件的时候，就被创建了，bean的实例化个数为1个，
      • 生命周期：应用加载，创建容器时，对象就被创建了
      • 只有容器在，对象就一直存活
      • 当应用卸载，销毁容器时，对象就会被销毁
    • prototype 多例的
      • 当调用getBean（）方法时实例化Bean，并且bean创建了多个
      • 生命周期：当使用对象时，创建新的对象实例
      • 只要对象在使用中，就会一直活着
      • 当对象长时间不在使用，就被java的垃圾回收器回收了
    • request web项目中的，spring创建一个bean的对象，将对象存入到request域中
    • session web项目中的，spring创建一个bean的对象，将对象存到session域中
    • global session web项目中，应用再portlet环境，如果没有protlet环境那么globalSession相当与session

  • bean标签的生命周期的配置：

    • init-method：指定类中初始化方法的名称
    • destory-method: 指定类中销毁方法的名称

  • bean实例化的三种方式

    • 无参构造方法实例化（默认就是无参构造方法实例化）
      • 会根据默认无参构造方法来创建类对象，如果bean中没有默认无参构造函数，将会创建失败
      <bean id="userDao" class="com.itheima.dao.impl.UserDaoImpl"/>
      1
    • 工厂静态方法实例化
      • 在bean标签里面添加factory-method属性等于="getUserDao"（getUserDao就是静态方法名）
      • 使用：将之前的bean中的全包类名，改成你得工厂的全包类名，然后加上属性factory-method=创建该bean的生成的方法
      public class StaticFactoryBean {
  public static UserDao createUserDao(){
      return new UserDaoImpl();
  }
}

# spring相关api

applicationContext：接口类型，代表应用上下文，可以通过其实例获得 Spring 容器中的 Bean 对象；其实现类如下：

  • ClassPathXmlApplicationContext ：它是从类的根路径下加载配置文件 推荐使用这种
  • FileSystemXmlApplicationContext ：它是从磁盘路径上加载配置文件，配置文件可以在磁盘的任意位置。
  • AnnotationConfigApplicationContext：当使用注解配置容器对象时，需要使用此类来创建 spring 容器。它用来读取注解

getBean()：获取组件示例，可以根据id或者class，注意当class时，只能是唯一

# spring注解开发

常用注解：

@Component	使用在类上用于实例化Bean
@Controller	使用在web层类上用于实例化Bean
@Service	使用在service层类上用于实例化Bean
@Repository	使用在dao层类上用于实例化Bean
@Autowired	使用在字段上用于根据类型依赖注入
@Qualifier	结合@Autowired一起使用用于根据名称进行依赖注入
@Resource	相当于@Autowired+@Qualifier，按照名称进行注入
@Value	注入普通属性
@Scope	标注Bean的作用范围
@PostConstruct	使用在方法上标注该方法是Bean的初始化方法
@PreDestroy	使用在方法上标注该方法是Bean的销毁方法

*  spring的后面配置就是注解配置：
*      value标签，注入普通属性，一般value值是${xxx}，在xml配置文件中引入properties，会去它里面找
*  spring新注解：
*      1.非自定义的bean配置
*      2.加载properties的文件配置
*      3.组件扫描配置
*      4.引入其他文件
*      使用spring新注解，上面这些都可以得到解决！
*
*  spring中的原始注解：
*          @Component("userDao")  ：使用在类上实例化Bean //如果注在UserDaoImpl的实例类头上，相当于在bean标签实例了，并且id=userDao
*          //下面三个没什么区别，只是为了区别语义，更好理解
*          @Controller ： 使用在web层类上用于实例化Bean
*          @Service ： 使用在service层上用户实例化Bean
*          @Repository  ：   用于在dao层上实例化Bean
*
*          //下面三个是注入注解，有一个问题，注在哪？
*          //之前学过bean中注入，有两种方式，set注入和构造器注入，我们既然使用注解了，那么不关心这个，我们关心的是什么被注入了，没错就是
*          //该组件内部，声明需要注入的其他组件的成员变量，那么就是注在这个成员变量头上
*          @Autowired   ：   使用在字段上用于根据类型依赖注入//根据uerDao.class这样
*          @Qualifier("userDao")   ：   结合Autowired一起使用根据名称进行依赖注入//根据id=userDao进行id注入
*          @Resource(name="userDao") : 相当于前两个!!//根据id注入，，一般都会使用这个
*
*          @Value("${a}")   ：   注入普通属性  //a就是在配置文件properties中的变量，当然，你得使用@PropertySource这个注解把配置文件加载进行容器
*          @Scope("prototype")   ：   标注Bean的作用范围,bean在哪？bean是组件，自然是放在类头上
*          @PostConstruct   ：   表示该方法是bean的初始化方法
*          @PreDestroy      ：   表示这个bean的销毁方法
*
*
*  spring中的新注解：
*          @Configuration   ：   用于指定当前类是一个Spring配置类
*          @ComponentScan(main.java)   ：   用于Spring在初始化容器时需要扫描的包
*          @Bean("dataSource")            ：   使用在方法上，标注该方法的返回值存储到Spring容器中  //以id = dataSource加载到容器中
*          @PropertySource  ：   用于加载properties文件中的配置
*          @Import          ：   用于导入其他配置类

# spring aop

* spring aop面向切面编程
*
*      定义：通过预编译方式和运行期动态代理实现程序功能的统一维护的一种技术
*      作用：在程序运行期间，在不修改源码的情况下对方法进行功能增强
*      优势：减少重复代码，提高开发效率，并且便于维护
*
*
*      aop动态代理技术：
*          jdk代理：基于接口的动态代理技术
*          cglib：基于父类的动态代理技术
*
*
*  aop开发过程：
*      需要编写的内容：
*          1.编写核心业务代码（目标类的目标方法）
*          2.编写切面类，切面类中有通知（增强功能方法）
*          3，在配置文件中，配置织入关系，即将哪些通知与那些连接点进行结合
*  aop技术实现内容：
*          spring框架监控切入点方法的执行。一旦监控到切入点方法被运行，使用代理机制，动态创建目标对象的代理对象，根据通知类别，在代理对象的
*          对应位置，将通知对应的功能织入，完成完整的代码逻辑运行，
*tgt
*  aop底层使用哪种代理方式
*          在spring中，框架会根据目标类是否实现了接口来决定采用哪种动态代理方式
*
*
*  目标对象（target）：代理的目标对象；还有切面对象，其中放增加方法
*  代理类（proxy）：一个类被aop织入增强后，就产生一个结果代理类
*  切入点（pointcut）：就是目标对象需要增强的方法
*  通知/增强（advice）：在切入点前后增加的切面对象中的增强方法
*  切面（aspect）：切入点和通知的结合，
*  织入（weaving）：切点和通知结合的过程

# springmvc流程

开发配置不多说了

开发步骤：

  • 导入SpringMVC相关坐标

  • 客户端发起请求测试

springmvc 流程图：

前端控制器流程：

  • 用户发送请求至前端控制器DispatcherServlet。
  • DispatcherServlet收到请求调用HandlerMapping处理器映射器。
  • 处理器映射器找到具体的处理器(可以根据xml配置、注解进行查找)，生成处理器对象及处理器拦截器(如果有则生成)一并返回给DispatcherServlet。
  • DispatcherServlet调用HandlerAdapter处理器适配器。
  • HandlerAdapter经过适配调用具体的处理器(Controller，也叫后端控制器)。
  • Controller执行完成返回ModelAndView。
  • HandlerAdapter将controller执行结果ModelAndView返回给DispatcherServlet。
  • DispatcherServlet将ModelAndView传给ViewReslover视图解析器。
  • ViewReslover解析后返回具体View。
  • DispatcherServlet根据View进行渲染视图（即将模型数据填充至视图中）。DispatcherServlet响应用户

  1. 前端控制器：DispatcherServlet

    用户请求到达前端控制器，它就相当于 MVC 模式中的 C，DispatcherServlet 是整个流程控制的中心，由 它调用其它组件处理用户的请求，DispatcherServlet 的存在降低了组件之间的耦合性。

  2. 处理器映射器：HandlerMapping

    HandlerMapping 负责根据用户请求找到 Handler 即处理器，SpringMVC 提供了不同的映射器实现不同的 映射方式，例如：配置文件方式，实现接口方式，注解方式等。

  3. 处理器适配器：HandlerAdapter

    通过 HandlerAdapter 对处理器进行执行，这是适配器模式的应用，通过扩展适配器可以对更多类型的处理 器进行执行。

* spring前端控制器，是什么？
*      需要我们手动导入依赖，进行配置，是springmvc的核心组件，其对应的组件就是Controller这个注解实例化的bean组件
*      @Controller
*      public class UserController {
*         @RequestMapping("/user")
*         public String getIndexPage(){
*             return "/index";
*         }
*     }
*     它干什么？它负责上面这个组件的成功运行！
*
*     接收请求数据：
*
*     @RequestMapping  用于建立请求url和处理请求方法之间的对应关系
*     位置：  一般情况下放在类和方法上都需要，放在类上@RequestMapping("/user")
*             放在这个类下面的方法上@RequestMapping("/age)
*             那么作用是，这个类（即Controller控制器组件）下面的方法映射的http的路径是/user/age，即复合路径
*
*     属性：   value，用于指定请求的的url，也是默认属性必带的
*             method，用于指定请求方式     @RequestMapping(method=RequestMethod.POST)
*             params，用于指定限制请求参数的条件，支持简单的表达式，要求参数的key和value的配置一模一样 例如@RequestMapping(params={"username"})表示请求参数必须带username
      并且当我们写好文件对应后，下面这些请求参数都会自动映射：
      基本类型参数
      POJO类型参数
      数组类型参数
      集合类型参数

* springmvc的页面跳转：
*      1.页面跳转
*              直接返回字符串
*              通过ModelAndView对象返回
*     2.回写数据（仅用于开发api，例如作为小程序的后端服务！）
*              直接返回字符串
*              返回对象或集合
*
*    1.页面跳转，返回以字符串形式：
*          1.1 return "index"  //返回普通页面，对应index。jsp
*          1.2 forward：xxx     //转发，转发到/WEB-INF/index。jsp
*          1.3 redirect：xxx    //重定向，重定向到/index。jsp
*          这里重定向和转发是一样的，也是javaWeb中的重定向不需要加虚拟目录

*          什么情况下用视图返回？当需要在给里面存入值即request域中session域中存入值

# springmvc拦截器

* springmvc 拦截器（interceptor）
* 类似于servlet开发中的filter 用于进行预处理和后处理
*
* 将拦截器按一定的顺序连接成一条链，这条链被称为拦截器链子。在访问被拦截的方法或字段时候，拦截器链子中的拦截器就会按其之前定义的顺序被调用
* 拦截器也是aop思想的具体实现
*
* filter过滤器和interceptor拦截器的不同点：过滤器是拦截在url-pattern配置了*之后的可以对所有资源拦截
*  拦截器只会拦截访问控制器方法，如果是jsp，html，css，image或者js是不会进行拦截的
*
*
*  拦截器快速入门：
*      1.创建拦截器实现HandlerInterceptor接口
*          preHandle（） 在目标方法执行之前，执行
*          postHandle（）  在目标方法执行之后，视图对象返回之前，执行
*          afterCompletion（）在所有流程结束之后执行
*      2.配置拦截器
*      3.测试拦截器的拦截效果
*
*      ==下面关于拦截器中的三个方法==
*      public class MyInterceptor1 implements HandlerInterceptor {
*     //在目标方法执行之前 执行
*     public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws ServletException, IOException {
*         System.out.println("preHandle.....");
*         //如果参数param的值是yes，则放行，不然转发到错误页面
*         String param = request.getParameter("param");
*         if("yes".equals(param)){
*             return true;
*         }else{
*             request.getRequestDispatcher("/error.jsp").forward(request,response);
*             return false;//返回true代表放行  返回false代表不放行
*         }
*     }
*
*     //在目标方法执行之后 视图对象返回之前执行
*     public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) {
*          //对请求的参数更改等一些操作！！
*         modelAndView.addObject("name","itheima");
*         System.out.println("postHandle...");
*     }
*
*     //在流程都执行完毕后 执行
*     public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) {
*         System.out.println("afterCompletion....");
*     }
* }
*
*
*
*
*      ==关于拦截器及其他相关的配置在spring-mvx.xml文件中==：
*      <!--1、mvc注解驱动-->
*     <mvc:annotation-driven/>
*
*     <!--2、配置视图解析器-->
*     <bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
*         <property name="prefix" value="/"/>
*         <property name="suffix" value=".jsp"/>
*     </bean>
*
*     <!--3、静态资源权限开放-->
*     <mvc:default-servlet-handler/>
*
*     <!--4、组件扫描  扫描Controller-->
*     <context:component-scan base-package="com.itheima.controller"/>
*
*
*     <!--配置拦截器-->
*     <mvc:interceptors>
*         <!--多个拦截器配置，配置文件中最上面的拦截器先执行，1的pre，2的pre；然后1的mid，2的mid，1的last，2的last-->
*         <mvc:interceptor>
*             <!--对哪些资源执行拦截操作-->
*             <mvc:mapping path="/**"/>
*             <bean class="com.itheima.interceptor.MyInterceptor2"/>
*         </mvc:interceptor>
*         <mvc:interceptor>
*             <!--对哪些资源执行拦截操作-->
*             <mvc:mapping path="/**"/>
*             <bean class="com.itheima.interceptor.MyInterceptor1"/>
*         </mvc:interceptor>
*     </mvc:interceptors>
