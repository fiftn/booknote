mtk下的sbe学习，以及对其定制化的应用级滑动策略

# SBE简介

这里主要先详细介绍下mtk的方案sbe

# 定义

目的：通过一系列的hint，辨识出当前用户场景，从SW Flow + HW Resource Control方面进行优化，达成性能最佳的同时功耗最低

SBE之前的架构，和使用SBE后的架构对比：

# SBE的作用

  • 解决非AOSP standard出图方式的app，其无法受到FPSGO 的管控

  • 通过identify更精确控制频率

  • 能够识别到应用启动和结束阶段，优化SW Flow

BoostModuleDispatcher.java

public final class BoostModuleDispatcher {

    private static final String TAG = "BoostModuleDispatcher";

    private static BoostModuleDispatcher sInstance = null;
    private static Object sLock = new Object();

    private static final SparseArray<BaseIdentify> SCENARIO_DIENTIFY = new SparseArray();

    public static BoostModuleDispatcher getInstance() {
        if (null == sInstance) {
            synchronized (sLock) {
                if (null == sInstance) {
                    sInstance = new BoostModuleDispatcher();
                }
            }
        }
        return sInstance;
    }

    public BoostModuleDispatcher() {
        rigisterScenarioCallback(BoostFwkManager.UX_SCROLL, ScrollIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_FRAME, FrameIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_LAUNCH, LaunchIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_IME, IMEIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_MSG, MsgIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_REFRESHRATE, RefreshRateIdentify.getInstance());
        rigisterScenarioCallback(BoostFwkManager.UX_VIEWEVENT, RefreshRateIdentify.getInstance());
        //SPD:add unlock anim support by sifeng.tian 20230522 start
        rigisterScenarioCallback(BoostFwkManager.UX_UNLOCK, UnlockIdentify.getInstance());
        //SPD:add unlock anim support by sifeng.tian 20230522 end
    }
    //场景分发函数
    public void scenarioActionDispatcher(BasicScenario scenario) {
        if (scenario == null) {
            LogUtil.mLogw(TAG, "No scenario to dispatcher.");
            return;
        }

        int scenarioId = scenario.getScenario();
        BaseIdentify identify =  SCENARIO_DIENTIFY.get(scenarioId);////识别场景ID
        if (identify == null) {
            LogUtil.mLogw(TAG, "Not found identify scenario.");
            return;
        }

        if (identify.isMainThreadOnly() && !Util.isMainThread()) {
            return;
        }

        identify.dispatchScenario(scenario);
    }
    //场景注册
    public boolean rigisterScenarioCallback(int scenarioId, BaseIdentify baseIdentity) {
        if (baseIdentity != null) {
            SCENARIO_DIENTIFY.put(scenarioId, baseIdentity);
            return true;
        }
        return false;
    }

}

BoostFwkManagerImpl.java

public final class BoostFwkManagerImpl extends BoostFwkManager {

    private static BoostFwkManagerImpl sInstance = null;
    private static BoostModuleDispatcher sBoostDispatcher = BoostModuleDispatcher.getInstance();
    private static Object sLock = new Object();
    
    //将自身类变成单例，提供对接接口
    public static BoostFwkManagerImpl getInstance() {
        if (null == sInstance) {
            synchronized (sLock) {
                if (null == sInstance) {
                    sInstance = new BoostFwkManagerImpl();
                }
            }
        }
        return sInstance;
    }

    /** hide */
    @Override
    public void perfHint(BasicScenario scenario) {
        if (Config.disableSBE()) {
            return;
        }
        sBoostDispatcher.scenarioActionDispatcher(scenario);
    }

    /** hide */
    @Override
    public void perfHint(BasicScenario... scenarios) {
        if (Config.disableSBE()) {
            return;
        }

        for (BasicScenario basicScenario : scenarios) {
            if (basicScenario == null) {
                continue;
            }
            sBoostDispatcher.scenarioActionDispatcher(basicScenario);
        }
    }
}

# UX_SCROLL && UX_MOVE_SCROLL

SBE对于滑动场景区分为两种：手指按下滑动、手指松开后的滑动

overscoller ：

  • 对于AOSP类型的场景，可以识别，这些部分场景会通过场景分发走到dispatchScenario这个函数；但是对于一些浏览器里面的界面是无法识别的，这类界面布局称为非AOSP类型；

onfling：

  • 那么，对于采用了 Flutter / Webview 的混合开发方案编写应用的这些界面是无法被识别的，也就是无法通过SBE的场景分发来到dispatchScenario这个函数，那么解决的方法是：使用scroll事件监听，这个类SimpleOnGestureListener是GestureDetector提供给我们的一个更方便的响应不同手势的类，其可以识别到所有的触屏事件，对于滑动事件，走到onfling函数下，然后通过sbebhint函数进行场景策略，并且在这个函数里将重复的overscoller等一些识别return掉
  • onfing 可以识别到所有的场景，包括overscoller

# 解决的痛点问题

  1. 目前平台支持全场景的UX_SCROLL和UX_MOVE_SCROLL, 全平台只能使用一套资源配置，无法精确细分。
  2. 以默认的SCROLL资源常常出现资源不足情况导致的卡顿(UI Thread等耗时的应用),对此调整会影响整机功耗
  3. 现有的UX_FLINGER策略无法覆盖非AOSP的应用，如flutter或webview开发的界面

# 实现功能

  • App fling白名单，可通过修改xml配置强制更改该场景下的滑动资源能力
  • 区分MOVE(手指按下滑动)和FLING(手指松开滑动)
  • xml文件加密
  • 云控

# 方案依赖

  • SBE：当前是通过SBE下发的命令进行识别，当然通过修改原生INTERACION实现
  • PowerHal：MTK平台对资源分配管控的功能。
  • 云控：tran_clound

# 导入条件

mtk平台D810以上

# 方案核心思想
