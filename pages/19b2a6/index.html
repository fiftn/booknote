操作系统基础

# 冯诺伊曼结构

哈佛结构更适合被用在对速度有需求的场景下，因为两个存储器加快了速度，也带来了架构的复杂。

# 操作系统

操作系统分类如图：

简单来说，操作系统肩负两个重任：

  1. 面向下层，统筹cpu、内存、flash、各种i/O设备的所有硬件组成元素
  2. 面向上层，为用户提供可用的人机交互界面，另一面给第三方程序研发提供敏捷、可靠、高效的API，

安卓的系统底层基本完全基于linux kernel来实现的，但是对进程，现场，内存的管理又有了自己的新特性

# 进程通信经典实现

进程间通信（IPC）：是指运行在不同进程中的若干线程间的数据交换；区别于RPC

# 共享内存

简单来说，就是每个进程将同一块物理内存区域和各自的虚拟地址空间关联时，这些进程就可以通过这块“共享内存”来完成IPC通信，当某进程更改了共享内存中的内容，其他进程也可以察觉到

进程：每个进程都有自己的进程控制块和地址空间，且都有一个与之对应的页表，负责将进程的虚拟地址与物理地址进行映射。（这一点，有点像c语言中的指针），通过内存管理单元进行管理。因此，可以通过修改页表来达到相同物理地址的映射实现

共享内存实现简单步骤：

  • 创建内存共享区
  • 映射内存共享区
  • 访问内存共享区
  • 进程间通信
  • 撤销内存共享区（撤销之前的映射操作，还原进程的原始物理地址）
  • 删除内存共享区（删除共享区域，linux还便于回收）

但是此时，有一个问题，也就是共享内存没有进程间的同步和互斥机制的。

​ 例如，当a的写入结束的之前，进程b就可以从共享内存区读取数据，进程a却没有办法，某种机制去阻止进程b的读操作，这样必然导致数据不一致性。

因此，为了实现进程的同步和互斥机制，经常将共享内存和信号量配合使用

# 管道

管道通信是unix中古老的通信机制

# 匿名管道

管道是半双工的，数据只能单项通信；需要双方通信时，建立两个管道；并且只能用于父子进程或者兄弟进程之间的通信

//例子：从键盘读取数据，写入管道，读取管道，写到屏幕
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>  //管道头文件
int main( void )
{
    int fds[2]; //管道的两个文件描述符，也就是管道fds[0]管道读通道；fds[1]管道写通道
    char buf[100];
    int len;
    
    if ( pipe(fds) == -1 )//创建匿名管道
    	perror("make pipe"),exit(1);
    
    // read from stdin
    while ( fgets(buf, 100, stdin) ) //循环向buf中写数据
    {
        len = strlen(buf);
        
        // write into pipe
        //先写再判断
        if (write(fds[1], buf, len) != len) //当实际写入管道的字符个数不等于buf长度时，就写入错误
        {
            perror("write to pipe");
            break;
        }
        
        memset(buf, 0x00, sizeof(buf));//将buf的内容置为0
        
        // read from pipe
        if ( (len=read(fds[0], buf, 100)) == -1 ) //先读再判断
        {
            perror("read from pipe");
            break;
        }
        
        // write to stdout
        if ( write(1, buf, len) != len ) //先写再判断
        {
            perror("write to stdout");
            break;
        }
        
    }
}

# FIFO

也就是命名管道，可在同一台计算机的不同进程之间或在跨越一个网络的不同计算机的不同进程之间，支持可靠的、单向或双向的数据通信。

​ 需要注意的是，命名管道同时u才能在进程的读写操作，也就是进程之间通信只需要一条管道即可，但是也就会出现进程的同步问题。

同步问题：当一个进程a在进行写操作的时候，另一个进程b开始读操作，这是进程a无法阻止进程b这个行为，最后导致两个进程的数据不统一，同步问题。

# Unix Domain Socket

简称UDS，这是一种争对单机内进程间通信提出来的，类似socket，被称为IPC Socket ，但是两者使用的方法类似，内部原理却有很大的区别。其通信方法和socket类似，借助#include <sys/socket.h>头文件

​ 安卓中使用最多的IPC机制就是Binder，其次就是UDS

# RPC

这是一个区别于IPC的通信机制，RPC涉及的通信双方通常是运行在两台不同的机器中

# 区别

共享内存是IPC最快最简单的通信方式之一。进程共享同一块内存，因为都是虚拟映射物理地址，因此访问共享内存区域和访问进程独有的内存区域一样快，并不需要通过系统调用或者其它需要切入内核的过程来完成。同时它也避免了对数据的各种不必要的复制。

消息队列、FIFO、管道的消息传递方式一般为：

  1. 服务器得到输入
  2. 通过管道，队列写入数据，通常需要从进程拷贝到内核
  3. 客户从内核拷贝到进程
  4. 然后从进程中拷贝到输出文件

共享内存实现：

  1. 从输入文件到共享内存区
  2. 从共享内存区输出到文件

# 同步机制的经典实现

在多道程序下，进程是并发运行的，为了协调进程之间的相互制约关系，引入进程同步的概念

  • 临界资源：一次只允许一个进程使用的资源称为临界资源
    • 进入区
    • 临界区，也就是正在进行时
    • 退出区，
    • 剩余区

同步：直接制约关系。进程之间为完成某种任务，协调工作

互斥：间接制约关系。进程a进入临界区，进程b必须等待；进程a占用临界资源退出临界区， 进程b才运行访问

# 信号量（Senaohore）

信号量与pv操作是dijkstra发明的，包括三个元素：semaphoreS 信号量、P wait()、V signal() 。

S用于指示共享资源的可用数量，P可用减少S计数，V则是增加它的计数

这里可以参考下我的博客文章 https://jiangkk.top/2022/11/27/1547/#title-1

这里的理解就是，对应的P是消费者，先执行对S执行-1操作，然后判断是否大于0，否则wait；S是对应的生产者，先对S执行+1操作，然后判断S是否大于0，否则唤醒下一个等待者。

# Mutex

在前面给到博客链接中的第一个例子就是这个mutex，经典取牛奶案例。也就是说当临界资源，只能取值true和false的时候，就可以使用这个mutex，和前面的信号量实现机制本质没区别。

# 管程（monitor）

前面信号量机制的缺点：当一些简单的应用场合情况下，信号量机制没有什么问题，但是涉及到庞大的系统时，就和c++中的new/delete操作，很容易导致发生问题。

管程是可以被多个进程/线程安全访问的对象或者模块，其中的方法都是受mutual exclusion ，保护的

# linux futex

在linux2.6中成为内核基线一部分，核心思想是在应用程序空间中就可以应对大多数的同步场景（只要当需要仲裁时才会进入内核空间），节省了不少系统调用和上下文切换时间。

fute在android中一个重要的应用场景就是art虚拟机。

# 操作系统内存管理基础

三个核心点：虚拟内存、内存分配与回收、内存保护。

# 虚拟内存

基本思想：

  • 将外部存储器的部分空间作为内存的扩展，如从硬盘中划分出4GB大小
  • 当内存资源不足的时候，系统将按照一定算法自动挑选优先级低的数据块，并将其存储到硬盘中
  • 后续如果需要用到硬盘中的这些数据块，系统会产生”缺页“指令，然后把他们交换回内存中
  • 这些操作都是由操作系统内核自动完成，并且对上层应用时完全透明的。

# 内存浅谈

物理地址就是内存的单元的绝对地址，在cpu实模式下，段基址+段内偏移地址 就是物理地址。

如图，cs是代码寄存器存储着段基址，ip寄存器则是偏移量，因此最初的cpu实模式下，控制单元的cs存储着内存中的段基址，和ip指针寄存器开始寻址，找到内存的地址。但是这种由寄存器保存内存的段基址，有一个很明显的缺点：因为ds中的总线和地址总线不一样，因此需要左移4位，这样导致了每次寻址的时候，段的起始地址不能是任何一个地方，而必须是16的倍数。因此，随着技术发展，当寄存器的位数到达了32位的时候，段寄存器的结构也发生了改变：将cs和ds这些段寄存器改成了段选择子寄存器，段的其实地址放在内存的某个地方，叫段描述符。

因此，为了兼容老一套的模式，cpu分为了实模式和保护模式，在保护模式下，段基址 + 段内偏移地址（逻辑地址） = 线性地址，但是如上所说，这个段基址不再是指段寄存器中存储的起始地址，而是被称为 段选择子 的东西，通过段选择子在GDT中找到真正的段基值，此外在这种模式下，如果未开启了分页功能，则线性地址就是物理地址

无论cpu处于啥模式，逻辑地址就是段内偏移地址。

# 逻辑地址

定义：也叫相对地址，是程序编译后产生的地址。具体的查看我onenote趣谈linux笔记

# 线性地址

偏移地址 + 基址 = 线性地址，也就是说线性地址是逻辑地址经过分段机制转换侯形成的，其基本思想（分段机制）：

  • 根据段选择子中的t1字段，得知段描述符存储在GDT或者LDT中
  • 通过cpu的两个寄存器GDTR/LDTR，获得GDT/LDT的存储地址
  • 根据段选择子中的INDEX字段，到GDT/LDT中查找到对应的段描述符
  • 根据段描述符获取此段的基地址
  • 由基地址+段内偏移值得到线性地址

整个流程，如图所示：

几个误区或者盲点：

  • 段表其实就在段选择子中，看起来很复杂但从老一套的实模式角度来说，还是在段寄存器和ip寄存器或者通过寄存器之间；这一系列的操作只不过是把之前的段寄存器中只存储基地址变复杂了
  • 段内偏移值还是从寄存器中获取，代码寻址就是ip指针寄存器，数据寻址就是通用寄存器
# 物理地址

这个比较好理解就是真实的地址。linux中基本不采用分段内存管理，而是采用分页的模式，那么分段就没有用了吗？其实不然，分段还可以做权限审核，根据段选择之中的DPL参数来判断是用户态还是内核态。

页：与分段机制不同，分页机制的操作对象是固定大小的内存块，称为页，一般情况下是4kb

页框：与页的概念对应，页框是对物理内存的最小操作单位，并且和页的大小是一致

如上图，线性地址的1、3、4、6页分别对应到物理地址1、2、3、4的页框。当前与物理内存没有映射的页2、5、7，说明他们不在内存中，因此访问会产生一个缺页中断。此时操作系统会自动接入处理，利用一定的算法将当前不常用的页调出内存，从而为这些缺失页腾出位置，然后将缺失页从外部存储器中重新读取回来，最后返回中断点继续操作。实际上内核的分页机制要比这个复杂很多。
