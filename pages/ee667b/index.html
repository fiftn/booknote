# 索引篇

# 索引基本概念

索引的基础语法？

创建索引
CREATE [ UNIQUE | FULLTEXT ] INDEX index_name ON table_name (index_col_name,... ) ;

查看索引
SHOW INDEX FROM table_name ;

删除索引
DROP INDEX index_name ON table_name ; 

eg：

name字段为姓名字段，该字段的值可能会重复，为该字段创建索引
CREATE INDEX idx_user_name ON tb_user(name);

phone手机号字段的值，是非空，且唯一的，为该字段创建唯一索引
CREATE UNIQUE INDEX idx_user_phone ON tb_user(phone);

为profession、age、status创建联合索引
CREATE INDEX idx_user_pro_age_sta ON tb_user(profession,age,status);

为email建立合适的索引来提升查询效率
CREATE INDEX idx_email ON tb_user(email);

mysql 中是不是为哪个字段创建索引，仅仅作用于查询这个字段？

是的，MySQL中创建索引的目的是为了提高查询效率。当为某个字段创建索引时，索引仅仅作用于查询这个字段的操作。创建索引后，MySQL会在内部建立一个数据结构，用于快速定位并访问这个字段的数据。在查询操作中，MySQL可以利用索引快速定位到符合查询条件的数据行，从而加快查询速度。但需要注意的是，索引并不会对更新、插入和删除操作产生直接的影响，而是会对这些操作的性能产生一定的影响。因此，在选择是否创建索引时，需要综合考虑查询频率和更新频率，以及对性能的需求。

什么情况下需要给字段创建索引？

在以下情况下，通常会考虑为字段创建索引：

  • 频繁作为查询条件的字段：如果某个字段经常用作查询的条件，那么为该字段创建索引可以提高查询的效率。例如，经常根据某个用户的 ID 进行查询操作，那么为用户 ID 字段创建索引可以加速查询。

  • 大数据量的字段：如果某个字段包含的数据量非常大，例如一个包含大量唯一值的字段，为该字段创建索引可以更快地定位到需要查询的数据。

  • 关联表的外键字段：如果某个字段用于关联其他表的外键关系，为该字段创建索引可以提高关联查询的效率。

  • 经常按照字段排序或分组：如果某个字段经常用于排序或分组操作，为该字段创建索引可以加速这些操作。

联合索引如何创建，什么是联合索引？

联合索引是指基于多个字段组合而创建的索引，也称为复合索引或组合索引。它可以用于加快多个字段组合查询的效率。要创建联合索引，可以使用以下语法：

CREATE INDEX index_name ON table_name (column1, column2, ...);
1

其中，index_name 是索引的名称，table_name 是表的名称，column1, column2, ... 是要包含在联合索引中的字段名，按照要求的顺序列出即可。

例如，如果要在表 users 上创建一个联合索引，包括 first_name 和 last_name 这两个字段，可以这样写：

CREATE INDEX idx_name ON users (first_name, last_name);
1

使用联合索引时，查询语句需要涉及到联合索引中的所有字段，才能发挥联合索引的作用

对于只涉及索引的一部分字段的查询，联合索引的效果可能会有所降低。同时，需要根据具体的查询需求和数据情况来选择字段的顺序，对于经常用于查询条件的字段，应该优先放在联合索引的前面，以获得更好的性能。

# mysql的索引选取

索引的本质其实就是利用数据结构，更快的查找数据。将某一类数据按特定的数据结构存储，后续查找这类数据即可找到相关联的数据，这便是索引。

目前可以支持的索引数据结构有：红黑树，b+树，b树，hash表,二叉树

那么为什么mysql使用的是b+树作为索引结构呢？

首先一点就是，红黑树 其实是 二叉树 的演变过来的，这里的二叉树也是指搜索二叉树，但是搜索二叉树有一个缺点就是如果数据插入的不好，最坏的情况下，它就是

一个顺序数组。因此，我们需要平衡旋转达到缩减树的高度，这里名词也就是平衡搜索二叉树，其包括了红黑树，AVL树等等，只需要记住红黑树是不那么严格要求的平衡，但即使这样

当数据过多的时候，红黑树依旧会达到令人恐怖的高度。由此可见红黑树行不通。

那么，选用b+树，而不是b树之前，我们需要了解这两者的概念，

总结下来，b+树的优点在于所有的数据都出现在叶子节点，叶子节点形成一个单链表，非叶子节点仅仅是起到一个索引数据的作用。

# 优化篇

# 从数据库设计出发

适度的违反范式

在开发应用程序时，数据库设计要最大程度的遵守三范式。当 然，三范式最大的问题在于查询时通常需要join很多表，导致查询效率很低。所以有时候基于性能考虑，我们需要有意的违反三范式。也就是适度的做冗余，以达到提高查询效率的目的。注意这里的反范式是适度的。

适当建立索引

索引可以有效的提高查询速度，但这个提高是以插入、更新、删除的速度为代价的。由于索引的存储结构不同于表的存储，一个表的索引所占空间比可能数据所占空间还大。这意味着我们在写数据库的时候做了很多额外的工作，而这个工作只是为了提高读的效率。因此，我们建立一个索引，必须保证这个索引不会“亏本”。一般需要遵守这样的规则：

○ 对经常更新的表就避免对其进行过多的索引。

○ 对经常用于查询的字段应该创建索引。

○ 数据量小的表最好不要使用索引。

○ 相同值较多的字段上不要建立索引（比如"性别"字段）。相反的，在不同值较多的字段上可以建立索引

对表进行水平划分

如果一个表的记录数太多了，比如上千万条，而且需要经常检索，那么我们就有必要化整为零了。如果我拆成100个表，那么每个表只有10万条记录。当然这 需要数据在逻辑上可以划分。一个好的划分依据，有利于程序的简单实现，也可以充分利用水平分表的优势。

比如系统界面上只提供按月查询的功能，那么把表按月拆分成12个，每个查询只查询一个表就够了。

对表进行垂直划分

有些表记录数并不多，但是字段却很多，导致表占用空间很大，检索表时需要执行大量I/O，严重降低了性能。解决方案是：可以把一部分字段拆分到另一个表，并且该表与原表是一对一的关系。

选择合适的引擎

在Oracle和SQL Server等数据库中只有一种存储引擎，所有数据存储管理机制都是一样的。而MySQL数据库提供了多种存储引擎，用户可以根据不同的需求为数据表选择不同的存储引擎。比如：

○ InnoDB存储引擎支持外键、支持事务、支持全文检索；

○ MyISAM存储引擎可以被压缩、不支持事务、不支持外键；如果需要执行大量的select语句，MyISAM存储引擎是更好的选择。

○ MEMORY存储引擎主要用于那些内容稳定的表，或者作为统计操作的中间表。

# 从索引出发

首先，我们可以查看到当前数据库到底是以查询为主，还是以增删改为主，从而为数据库优化提供参考依据。 如果是以增删改为主，我们可以考虑不对其进行索引的优化。 如果是以查询为主，那么就要考虑对数据库的索引进行优化了。

SHOW GLOBAL STATUS LIKE 'Com_______';
1

该条命令可以查看数据库中的增删改查的使用语句次数。其实大多数，都是以查询为主，因此该如何定位优化那些慢的sql语句呢？那就需要mysql中的慢查询日志了

配置开启慢日志：

/etc/my.cnf

# 开启MySQL慢日志查询开关
SET GLOBAL slow_query_log = 1;

# 设置慢日志的时间为2秒，SQL语句执行时间超过2秒，就会视为慢查询，记录慢查询日志
SET GLOBAL long_query_time = 2;

#配置完成后，需要重启MySQL服务
systemctl restart mysqld;

# 查询系统变量，开关情况
SHOW VARIABLES LIKE 'slow_query_log';

# 查询慢日志的阈值时间
SHOW VARIABLES LIKE 'long_query_time';

# 查看慢日志文件的路径
SHOW VARIABLES LIKE 'slow_query_log_file';

下面是explain关键字，输出的一些字段的含义

字段 含义
id select查询的序列号，表示查询中执行select子句或者是操作表的顺序 (id相同，执行顺序从上到下；id不同，值越大，越先执行)。
select_type 表示 SELECT 的类型，常见的取值有 SIMPLE（简单表，即不使用表连接 或者子查询）、PRIMARY（主查询，即外层的查询）、 UNION（UNION 中的第二个或者后面的查询语句）、 SUBQUERY（SELECT/WHERE之后包含了子查询）等
type 表示连接类型，性能由好到差的连接类型为NULL、system、const、 eq_ref、ref、range、 index、all 。
possible_key 显示可能应用在这张表上的索引，一个或多个。
key 实际使用的索引，如果为NULL，则没有使用索引。
key_len 表示索引中使用的字节数， 该值为索引字段最大可能长度，并非实际使用长 度，在不损失精确性的前提下， 长度越短越好 。
rows MySQL认为必须要执行查询的行数，在innodb引擎的表中，是一个估计值， 可能并不总是准确的。
filtered 表示返回结果的行数占需读取行数的百分比， filtered 的值越大越好。
