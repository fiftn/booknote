# android抓取火焰图

# simpleperf简介

simpleperf是Android平台的一个本地性能分析工具，主要针对native层。它的命令行界面与Linux-tools perf大致相同，但是它还支持一些针对Android特有的选项。

simpleperf的基本原理： 现代CPU具有一个硬件组件，称为性能监控单元（PMU）。PMU具有一些硬件计数器，记录CPU周期，指令数，cache命中次数等。Linux内核将这些硬件计数器包装到硬件perf（hardware perf events）事件中，还提供了独立于硬件的软件事件和跟踪点事件，通过perf_event_open系统调用将这些提供给用户。 简单来说，simpleperf的工作原理就是根据的设置的频率进行采样，在CPU上（每个核上都有）产生一个中断，中断到来时记录当前CPU正在运行哪个进程的哪个函数。最终的结果是一个统计量，记录的是一段时间内某个函数被命中的次数百分比，百分比越大说明这段时间这个函数占用的cpu资源越多。

simpleperf主要具有三个主要功能：

stat：在一个时间段内被分析的进程中发生了多少事件，其原理如下：

  1. 给定用户选项，通过对Linux内核进行系统调用来启用分析
  2. Linux内核在调度到被分析进程时启用计数器
  3. 分析之后，从内核读取计数器，报告计数器摘要

record：在一段时间内记录剖析进程的样本，其原理如下：

  1. 给定用户选项，通过对Linux内核进行系统调用来启用分析
  2. 在simpleperf和Linux内核之间创建映射缓存区
  3. Linux内核在调度到被分析进程时启用计数器
  4. 每次给定数量的事件发生时，Linux内核将样本转储到映射缓存区
  5. 从映射缓存区读取样本并生成perf.data

report：读取"perf.data"文件及所有被剖析进程用到的共享库，并输出一份报告，展示时间消耗到了哪里

其他子命令：simpleperf list用于列出设备上所有可用的事件（由于内核的差异，不同的设备可以支持不同的事件）

参数详解

-p：指定进程
-t：指定线程
-a：全系统运行
-e：指定事件（CPU cycle、instructions等）
--duration：指定监控时长，单位s（中途可以通过 Ctrl+C 终止监控）
--interval：指定打印间隔，单位ms
--per-core：查看事件在不同CPU核上的分布
--cpu：指定CPU
-f：指定转储记录的频率（受监控线程运行时每秒转储 f 条记录）
-c：指定转储记录的间隔（每当发生 c 个事件时转储一条记录）

# 抓取火焰图步骤

  • 抓取perf文件
simpleperf record -p [pid] -g --duration [time] --call-graph fp -o /sdcard/perf.data
#-g：采集函数调用关系；
#--call-graph fp 生成函数调用图，64系统（32位用--call-graph dwarf），这个参数必须有，否则无法生成火焰图
#若需要文本报告可使用report命令
#simpleperf report -g -i /sdcard/perf.data -o /sdcard/report.txt

# 如何分析火焰图

y 轴表示调用栈，每一层都是一个函数。调用栈越深，火焰就越高，顶部就是正在执行的函数，下方都是它的父函数。x 轴表示抽样数，如果一个函数在 x 轴占据的宽度越宽，就表示它被抽到的次数多，即执行的时间长。注意，x 轴不代表时间，而是所有的调用栈合并后，按字母顺序排列的。火焰图就是看顶层的哪个函数占据的宽度最大。只要有"平顶"（plateaus），就表示该函数可能存在性能问题。颜色没有特殊含义，因为火焰图表示的是 CPU 的繁忙程度，所以一般选择暖色调。
