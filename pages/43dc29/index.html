一些个人折腾中的排错

首先，值得肯定的是，遇到错误，一定需要冷静，并且知其所以然，明白其中的原理，有目的的进行排除。而不是一味的尝试，甚至不知所措，瞎乱百度，这样只会浪费时间。！

# vscode远程连接内网穿透的虚拟机报错

首先，当我在vscode配置完连接信息后，启动连接，报错连不上。这时候需要冷静。

一般的情况下，我们是连接到服务器，但是这里是内网穿透，于是多了一层内网穿透的知识，也就是需要我们提前去check的。如果check了内网穿透没有问题的话，那么我们 就可以按照老思路继续排查了

  • 检测ip地址和端口信息

Escape character is '^]'.
Connection closed by foreign host.

  • 防火墙？端口是否存在防火墙？

因为，我们已经连接了上了一瞬间，那么防火墙其实是ok的

  • 端口对端的服务，是否响应了？

这点，我一开始没有意识到，这里被closed，其实就是端口对端服务出现了问题，首先看下ssh服务是否存在：

# 查看服务是否存在
apt list --installed | grep openssh-server

# 不存在，安装ssh服务
apt install openssh-server -y

# 如果存在，查看服务的状态
systemctl status ssh

# 激活该服务
systemctl start ssh

排查出服务没有启动，但是还没有结束，因为还是连接不上，这时候如何猜想分析？

其实，应该也能猜到，就是密码和用户名可能不对，这时候就需要对ssh服务有一定了解

如果你的密码和root用户是正确的，但是还是fail了，其实就是ssh的默认配置：其是允许密码登录的，默认是只允许密匙方式

其实，如果我们成熟一点，应该知道ssh就是通过ssh服务来的，可以参考这个教程，搭建ssh服务以及samba驱动, 参考教程：https://blog.csdn.net/m0_57213770/article/details/134175585

如果还是出现了报错：

root@CQSWWANGTJ:~/.ssh# ssh -T git@gitee.com
ssh: Could not resolve hostname gitee.com: Temporary failure in name resolution

sudo sed -i 's/nameserver .*/nameserver 8.8.8.8/' /etc/resolv.conf

# docker无法启动

年后回家发现docker无法启动，拿着14寸的小笔记本，还没鼠标，在那排错，实在难受，一直都没解决，年后来公司，冷静看了下，是一个很简单的小问题，

心得反思： 工作环境和效率很重要，如果是为了让自己看起来很努力，不如放手痛快去玩

不多说了，排查过程如下

首先，第一个反应就是需要查看docker的报错日志，docker没启动，看报错日志很重要。

这里ps一下： 尽量别用新技术，比如ubuntu里的snap安装软件包，新技术的生态都不完善，遇到问题很难受

# 原生的docker查看日志
sudo journalctl -u docker

# snap下安装的docker查看报错日志
sudo journalctl -u snap.docker.dockerd
