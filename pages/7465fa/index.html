perfetto入门指南

# 背景

官方文档教程；https://perfetto.dev/docs/

Perfetto UI 是 Android 9 (P)中引入的全新平台级跟踪工具，从 Android 11(R) 开始是默认开启的，在 Android 9 (P) 和 Android 10 (Q) 上需要打开相应的开关才能使用这个功能：

# Needed only on Android 9 (P) and 10 (Q) on non-Pixel phones.
adb shell setprop persist.traced.enable 1
1
2

与传统的 Systrace 相比，Perfetto 有以下优点：

  • 流畅，打开较大的trace文件比systrace优秀太多
  • Binder 跨进程点击跳转，跟踪方便，不像 Systrace 通过指引线跟踪 Binder 跳转
  • 支持置顶你感兴趣的线程，放在一起分析更容易
  • 看线程被谁唤醒非常方便

# 命令行抓取

使用手机抓取的方式，好处就是不需要连接电脑，可以离线抓取，比较适用于日常体验，但是 Perfetto 有其他强大的功能，需要使用连接电脑才能发挥，下面介绍一下通过可视化界面修改配置信息的方法。

2.1 Recording settings

首先是选择录制的设置，主要有三种模式，不同的模式代表不同的抓取方式：

  • Stop when full：停止工作受 Max duration 和 buffer size 影响，一旦满足其中一个条件，Perfetto 将会停止；
  • Ring buffer：只会收到 Max duration 的影响，时间到了就停止抓取 Trace，但是 Trace会有被 overwrite 的风险
  • Long trace：用于长时间地抓取 Trace，但是由于需要定时将 Buffer 中的 Trace 写到文件里面去，会有 IO 的影响，长时间模式更适合使用手机抓取，这里不做太多解释。

2.2 Recording command

录制命令是根据所有的配置信息，自动生成的一个命令集合，在 Linux 或者 Mac 平台上，只需要运行这个指令就可以抓取 Trace 了，在 Windows 上会有一点不同，这个后面会详细讲解，这里只需要初步了解其结构：

2.3 CPU

CPU 里面有4个选项，分别是：

  • Coarse CPU usage counter：CPU使用量，可以看到 CPU 的负载情况，需要打开；
  • Scheduling details：在 CPU 时间片上运行的进程名称，可以了解进程在 CPU 上的运行情况，需要打开；
  • CPU frequency and idle states：CPU 频率情况，可以了解此时 CPU 的频率是多少，需要打开；
  • Syscalls：在 userdebug 的版本可用，可以看到 kernel 层的调用情况，有 kernel 层调试需要的可以打开，一般情况下不开。
  • 推荐配置是打开前3个：

2.4 GPU

GPU 里面有2个选项，分别是：

  • GPU frequency：GPU 的频率，场景中有用到 GPU 合成时需要打开；
  • GPU memory：只在 Android 12 以上支持这个功能，可以看到 GPU 的内存使用情况。

2.5 Power

Power 这块配置看起来跟功耗相关，不过暂时不了解，等待后续功耗的同事补充，对性能来说关系不大，可以不打开：

2.6 Memory

配置命令的方式一般用于复现问题，而 Memory 相关的参数可以直接dump查看，除非存在一些IO问题需要查看内存情况，平时不建议在 Trace 中打印，信息太多容易干扰视线。 打开 Memory 信息后可以查看到整体的内存情况：

adb shell "echo 1 > /sys/devices/system/cpu/perf/enable"

adb shell "echo 1 > /sys/kernel/tracing/events/mtk_events/perf_index_gpu/enable"
adb shell "echo 1 > /sys/kernel/tracing/events/perf_tracker/perf_index_gpu/enable"

# Callstack sampling

Periodically records the current callstack (chain of function calls) of processes.

打开TAG后，抓取的trace信息如下：

主要说下如何看这个堆栈，这个是一个从函数出发点开始，也就是图的最底部开始

art::ArtMethod* art::ClassLinker::ResolveMethod(unsigned int, art::Handle<art::mirror::ClassLoader>, art::ArtMethod*, unsigned int)

从这个方法开始的ResolveMethod ：

c++中的堆栈遵循下面的规则：<返回类型> <命名空间>::<类>::<方法>(<参数列表>)

于是对这个函数进行拆解：

返回类型：

art::ArtMethod*：这是一个指向 art::ArtMethod 对象的指针。
命名空间和类：

art::ClassLinker：表示 art 命名空间中的 ClassLinker 类。
方法名称：

ResolveMethod：方法的名称。
参数列表：

unsigned int：第一个参数是无符号整数类型。
art::Handle<art::mirror::ClassLoader>：第二个参数是 art::Handle 包装的 art::mirror::ClassLoader 对象。
art::ArtMethod*：第三个参数是指向 art::ArtMethod 对象的指针。
unsigned int：第四个参数是无符号整数类型。
