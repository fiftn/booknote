# 生命周期管理

# run

创建一个新的容器并运行一个命令，简单例子

docker run --name mynginx -d nginx:latest
1

使用镜像nginx:latest以后台模式启动一个容器,并将容器的80端口映射到主机随机端口。

# start/stop/restart

  • docker start :启动一个或多个已经被停止的容器
  • docker stop :停止一个运行中的容器
  • docker restart :重启容器

比如下面这个就是启动一个容器（后面可以填容器名字和容器id）

docker start myrunoob
1

# kill

  • docker kill 杀掉一个运行中的容器。

杀掉运行中的容器mynginx

docker kill -s KILL mynginx
1

# rm

  • docker rm 删除一个或多个容器。

比如我们强制删除容器 db01、db02：

docker rm -f db01 db02
1

# pause/unpause

  • docker pause 暂停容器中所有的进程。
  • docker unpause 恢复容器中所有的进程。

暂停数据库容器db01提供服务。

docker pause db01
1

# create

  • docker create 创建一个新的容器但不启动它

使用docker镜像nginx:latest创建一个容器,并将容器命名为myrunoob

docker create  --name myrunoob  nginx:latest
1

# exec

  • docker exe 在运行的容器中执行命令

在容器 mynginx 中以交互模式执行容器内 /root/runoob.sh 脚本:

docker exec -it mynginx /bin/sh /root/runoob.sh
1

# 深刻理解

# 数据卷的挂载

选择数据卷的挂载方式很重要，不过大多数情况下，我们都是选择文件目录映射

  • 在 Docker 中，挂载方式可以分为具名挂载、匿名挂载和指定路径挂载，其区别如下：

具名挂载：使用卷名进行挂载，卷名定义在 Docker 中，这样可以使容器和主机之间共享数据。 例如：-v mydata:/container/path

匿名挂载：只指定容器内的挂载路径，不指定卷名，Docker 会自动生成一个匿名卷。匿名挂载一般用于临时存储数据。 例如：-v /container/path

指定路径挂载：直接指定宿主机上的路径和容器内的路径进行挂载，适用于将宿主机上的特定路径挂载到容器内部。 例如：-v /host/path:/container/path

举一个例子：

# 在这个例子中，-v /docker/path:/root 表示将 Docker 中的 /docker/path 路径挂载到宿主机的 /root 目录下。<image_name> 则是你要运行的容器镜像的名称。
docker run -v /docker/path:/root -d <image_name>
1
2
  • 不同的挂载方式在 Docker 中各自有不同的应用场景：

具名挂载：适用于需要多个容器之间共享数据的情况。通过给卷取一个具有意义的名称，可以方便地在不同的容器之间共享数据，同时还能更容易地管理这些卷的生命周期。这种挂载方式适合需要持久化存储数据，并且想要在多个容器之间共享这些数据的场景。

匿名挂载：适用于临时的、无需持久化的数据存储需求。匿名挂载为应用提供了临时的存储空间，并且可以确保容器终止时这些数据会被自动清理。这种挂载方式适合用于临时的、无需持久化的数据存储，比如一些临时的计算结果或缓存。

指定路径挂载：适用于需要将宿主机上的特定路径挂载到容器内部的场景。它允许将宿主机上的文件或目录直接挂载到容器内部，这种方式可以方便地与宿主机共享特定的文件或目录。这种挂载方式适合需要在容器与宿主机之间共享特定文件或目录的情况

综上所述，具名挂载适合需要持久化数据并在多个容器之间共享数据的场景，匿名挂载适合临时的数据存储需求，而指定路径挂载则适合需要与宿主机共享特定文件或目录的情况。

接下来的解决方式就要两种，需要了解docker的网络配置模式

  • 最简单的方式，我们启动jenkins的时候需要加入：
--network host

配置和主机一样的网络访问，但是这样配置的端口转发也就不生效了，会和主机共用网络，占用端口

  • 第二种方式，docker中默认的是桥接的模式，那显然这里桥接模式被一些原因阻拦了，配置了但是却没有网络，需要排查：

我这里的理解是，docker默认使用的桥接的模式，桥接模式需要主机ubuntu上要端口转发的功能，目前我了解到的，防火墙有这个功能：

net.ipv4.ip_forward = 1

可能的错误：今天说的防火墙重启后，容器不能联网的问题就发生在bridge模式下，原因是在bridge模式下，docker会默认写入iptables规则，但是这些规则不知为何，没有写入磁盘所以当防火墙重启后，规则丢失，容器自然无法上网。 解决办法就是重启docker，重写规则，所以一般生产要不就是关闭防火墙起docker，要不就开启防火墙起docker，过程中不要让防火墙重启；
