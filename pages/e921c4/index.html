android:layout_width和android:layout_height有三种参数：match_parent,wrap_content和固定值

  • match_parent表示让当前控件大小和父布局大小一样
  • wrap_content表示当前控件刚好包含住里面内容
  • 固定值：就是一个固定的尺寸，单位一般为dp

android:gravity可选值：top、bottom、start、 end、center

# 注册监听器方式二：接口注册
class MainActivity : AppCompatActivity(), View.OnClickListener {
 	override fun onCreate(savedInstanceState: Bundle?) {
 	super.onCreate(savedInstanceState)
 	setContentView(R.layout.activity_main)
 	button.setOnClickListener(this)
 	}
 	override fun onClick(v: View?) {
 	when (v?.id) {
 		R.id.button -> {
 		// 在此处添加逻辑
 		}
 	}
  }
}

# 控件可见属性

android:visibility可以指定控件的可见性

  • 可选值：visible、invisible和gone
  • visible表示可见，默认属性
  • invisible表示不可见，但占据原来位置大小
  • gone表示控件消失

# 创建自定义控件

引入布局只能解决静态的重复代码问题，但是如果布局中有一些控件要求能够响应时间，那么需要在新的activity中编写注册事件，这时，自定义控件可以帮助我们解决问题

既然要动态代码也同样实现，并且还是自定义控件，那么怎么实现呢？

没错，继承控件，把重复的动态代码也放进去

class TitleLayout(context: Context, attrs: AttributeSet) : LinearLayout(context, attrs) {
     init {
     LayoutInflater.from(context).inflate(R.layout.title, this)
     titleBack.setOnClickListener {
     val activity = context as Activity
     activity.finish()
     }
     titleEdit.setOnClickListener {
     Toast.makeText(context, "You clicked Edit button", Toast.LENGTH_SHORT).show()
     }
  }
}

# kotlin:延迟初始化和密封类

# 延迟初始化

当变量被声明为null的时候，在kotlin中，下次调用就需要进行判空处理，即使你确切知道它不为空，比如

private var a:BaseActivity? = null
a?.test()
1
2

这里，a需要加上?进行判空处理，这时延迟初始化即可帮我们简化代码

private lateinit var a:BaseActivity
a.test()
1
2

使用关键字lateinit即可对变量进行延迟初始化，这时也不必对它进行赋值为null，如果我们的确信出了问题，也不必担心有bug，此时程序一定会奔溃，抛出UninitializedPropertyAccessException异常

::adapter.isInitialized可用于判断变量adapter是否已经初始化

if (!::adapter.isInitialized) {
 	adapter = MsgAdapter(msgList)
}
