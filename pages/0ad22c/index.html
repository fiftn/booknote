Handle机制

参考链接：https://cloud.tencent.com/developer/article/1963296?from_column=20421&from=20421

简介

​一、Android Handler 机制核心原理

  • ​1. 核心组件

​Handler：消息处理器，负责发送和处理消息。

​Looper：消息循环器，不断从 MessageQueue 中取出消息。

​MessageQueue：消息队列，存储待处理的 Message。

​Message：消息的载体，包含数据和目标 Handler。

  • ​2. 工作流程

​Looper 初始化：主线程默认已创建 Looper，子线程需手动调用 Looper.prepare() 和 Looper.loop()。

​消息发送：Handler 发送 Message 到 MessageQueue。

​消息循环：Looper 不断从 MessageQueue 取出消息，分发给对应 Handler 处理。

demo

主线程: 创建looper，主线程自动创建，无需初始化； 接着主线程创建handler,会默认绑定给主线程的looper,重写handleMessage方法用来识别消息做处理；接着需要发送消息的子线程，则调用刚刚的mHandler对象的sendMessage方法来发送消息。（子线程会有些不一样，但基本类似；需要手动创建looper，然后绑定到hander上）

public class MainActivity extends AppCompatActivity {
    
    public TextView mTextView;
    public Handler mHandler;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        mTextView = (TextView) findViewById(R.id.show);

        // 步骤1：在主线程中 通过匿名内部类 创建Handler类对象
        mHandler = new Handler(){
            // 通过复写handlerMessage()从而确定更新UI的操作
            @Override
            public void handleMessage(Message msg) {
                // 根据不同线程发送过来的消息，执行不同的UI操作
                switch (msg.what) {
                    case 1:
                        mTextView.setText("执行了线程1的UI操作");
                        break;
                    case 2:
                        mTextView.setText("执行了线程2的UI操作");
                        break;
                }
            }
        };
        // 采用继承Thread类实现多线程演示
        new Thread() {
            @Override
            public void run() {
                try {
                    Thread.sleep(3000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                 // 步骤3：创建所需的消息对象
                 Message msg = Message.obtain();
                 msg.what = 1; // 消息标识
                 msg.obj = "A"; // 消息内存存放

                 // 步骤4：在工作线程中 通过Handler发送消息到消息队列中
                 mHandler.sendMessage(msg);
            }
        }.start();
        // 步骤5：开启工作线程（同时启动了Handler）

        // 此处用2个工作线程展示
        new Thread() {
            @Override
            public void run() {
                try {
                    Thread.sleep(6000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                // 通过sendMessage（）发送
                 // a. 定义要发送的消息
                 Message msg = Message.obtain();
                 msg.what = 2; //消息的标识
                 msg.obj = "B"; // 消息的存放
                 // b. 通过Handler发送消息到其绑定的消息队列
                 mHandler.sendMessage(msg);
            }
        }.start();

    }

}

  1. 创建looper

主线程：系统自动创建 Looper，无需手动初始化。

​子线程：必须手动调用 Looper.prepare() 和 Looper.loop()

new Thread(() -> {
    Looper.prepare();      // 初始化 Looper
    Handler handler = new Handler(); 
    Looper.loop();         // 启动消息循环

  • Looper.prepare()：

检查当前线程是否已绑定 Looper（避免重复创建）。

创建一个 MessageQueue（消息队列）并与当前线程绑定。

将 Looper 对象存储在线程的 ThreadLocal 中（确保线程隔离）。

// 源码：Looper.prepare()
public static void prepare() {
    prepare(true);
}

private static void prepare(boolean quitAllowed) {
    if (sThreadLocal.get() != null) {
        throw new RuntimeException("Only one Looper per thread!");
    }
    sThreadLocal.set(new Looper(quitAllowed));
}

  • 消息入队

这里会调用nativeWake唤醒Looper

// 源码：MessageQueue.enqueueMessage()
boolean enqueueMessage(Message msg, long when) {
    synchronized (this) {
        msg.markInUse();
        msg.when = when;
        Message p = mMessages;
        if (p == null || when == 0 || when < p.when) {
            // 新消息插入队列头部
            msg.next = p;
            mMessages = msg;
            needWake = mBlocked; // 是否需要唤醒 Looper
        } else {
            // 按时间顺序插入队列
            Message prev;
            for (;;) {
                prev = p;
                p = p.next;
                if (p == null || when < p.when) {
                    break;
                }
            }
            msg.next = p;
            prev.next = msg;
        }
        if (needWake) {
            nativeWake(mPtr); // 唤醒休眠的 Looper
        }
    }
    return true;
}

  • Looper 循环处理消息

Looper.loop() 不断从 MessageQueue 取出消息。消息分发给对应的 Handler 处理。

MessageQueue.next() 从队列头部取出消息。若队列为空，调用 nativePollOnce() 进入休眠（通过 Linux 的 epoll 机制释放 CPU）。当新消息到达时，通过 nativeWake() 唤醒线程。

msg.target 是发送消息的 Handler 对象。若消息包含 Runnable（post(Runnable) 发送），直接执行 Runnable.run()。否则调用 Handler.handleMessage()。

// Looper.loop() 源码核心逻辑（简化）
public static void loop() {
    final Looper me = myLooper();
    final MessageQueue queue = me.mQueue;
    for (;;) {
        Message msg = queue.next(); // 可能阻塞
        if (msg == null) return;    // 退出循环
        msg.target.dispatchMessage(msg); // 分发消息
        msg.recycleUnchecked();     // 回收消息到全局池
    }
}

# Q && A

子线程需要创建 Looper 的情况

  1. 是否需要处理消息队列（无论消息来源）​ ​场景一：接收其他线程的消息 ✅ 必须创建 Looper ​示例：主线程向子线程发送任务指令（如数据库操作）。

​场景二：处理本线程的延时/周期任务 ✅ 必须创建 Looper ​示例：子线程自身需要执行定时任务（如每隔 5 秒上报日志），无需其他线程介入。

class WorkerThread extends Thread {
    private Handler mHandler;

    @Override
    public void run() {
        Looper.prepare();    // 创建 Looper
        mHandler = new Handler() {
            @Override
            public void handleMessage(Message msg) {
                // 处理任务
            }
        };
        Looper.loop();       // 启动消息循环
    }
}

# 深入思考

了解了刚刚的handle基本用法，深入思考下，如果我来设计一个handle，会遇到什么难点？

如何实现子线程发送消息，主线程接受到的，跨线程通信的。 我理解是子线程发送消息，调用的是主线程的handler； 本质上其实是我写一个对象在主线程里，这个对象有一个方法可以发送消息到对象里的队列里，因为子线程可以访问主线程里的成员对象，所以就能够调用方法发送消息了？

没错，这么理解是正确的。所谓的跨线程通信，不过就是线程a能够访问线程b的对象里的方法，这个方法可以将message放到线程b里的队列或者数组里

接着我刚才的理解，那么我创建了这样一个对象，子线程调用其方法能给发送信息写到一个队列或者数组里， 那么，主线程怎么知道消息来了呢？ 比如我自己写我会每隔1ms去判断队列是否为空，有就取出消息。但我知道这样肯定不对， handler又是如何做到的？现在问题是，我创建了这个对象，能调用方法发送信息到我想要的队列或者数组里，但是，主线程是如何知道有消息了? 这才是handle的核心

  • Handler 的实现核心在于「阻塞-唤醒机制」（而非轮询）；其实本质上还是要追溯到epoll

​当消息队列为空时：主线程的 Looper.loop() 会调用 MessageQueue.next()，该方法通过 nativePollOnce() ​阻塞主线程​（进入休眠状态，不消耗 CPU）。

当子线程发送消息时：Handler.sendMessage() 最终会调用 MessageQueue.enqueueMessage()，该方法除了将消息插入队列，还会通过 nativeWake() ​唤醒主线程。

// 主线程的 Looper 循环
public static void loop() {
    final Looper me = myLooper();
    final MessageQueue queue = me.mQueue;
    while (true) {
        // 阻塞等待消息（通过 nativePollOnce）
        Message msg = queue.next(); 
        if (msg == null) return;
        // 分发消息给 Handler
        msg.target.dispatchMessage(msg);
    }
}

// MessageQueue.enqueueMessage()
boolean enqueueMessage(Message msg, long when) {
    synchronized (this) {
        // 插入消息到队列
        ...
        // 唤醒主线程（通过 nativeWake）
        if (needWake) nativeWake(mPtr);
    }
}

nativePollOnce() 和 nativeWake()：是 JNI 方法，底层通过 Linux 的 epoll 和 ​管道（pipe）​** 实现线程间通信。

  • nativePollOnce()：主线程在消息队列为空时，通过 epoll 监听管道上的读事件，进入阻塞状态。
  • nativeWake()：子线程发送消息时，向管道写入数据，触发 epoll 的读事件，唤醒主线程

Q1: 为什么主线程不会因为 Looper.loop() 卡死？

​Linux 的 epoll 机制：当 MessageQueue 为空时，nativePollOnce() 通过 epoll_wait 进入休眠，释放 CPU 资源。​新消息到达时：通过 pipe 的写操作唤醒线程，此时会处理输入事件、广播等消息

Q2: Handler.post(Runnable) 和 sendMessage() 有何区别？

​本质相同：内部都会将 Runnable 封装为 Message（callback 字段） 代码风格差异：

// post 写法更简洁
handler.post(() -> { /* code */ });

// sendMessage 更灵活（可携带 what/arg 等数据）
Message msg = handler.obtainMessage(MSG_TYPE, data);
handler.sendMessage(msg);

Q4: 主线程 Looper 的休眠唤醒机制是如何实现的？

​底层依赖 Linux 的 epoll：当消息队列为空时，调用 nativePollOnce() 进入休眠。 ​输入事件到达时：通过 nativeWake() 写入文件描述符唤醒线程。

线程切换实现原理

​发送消息时：消息被插入到目标线程的 MessageQueue（线程安全通过 synchronized 保证）。​处理消息时：目标线程的 Looper 从队列取出消息，调用 Handler.handleMessage()，从而切换到目标线程执行。
