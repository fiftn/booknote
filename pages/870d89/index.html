# 使用Intent在Activity之间穿梭

Intent是Android程序中各组件之间进行交互的一种重要方式，它不仅可以指明当前组件想要执 行的动作，还可以在不同组件之间传递数据。Intent一般可用于启动Activity、启动Service以 及发送广播等场景。

Intent大致可以分为两种：显式Intent和隐式Intent。

# 使用显示intent

button1.setOnClickListener {
 	val intent = Intent(this,MainActivity2::class.java)
     startActivity(intent)
}

# 使用隐式intent

隐式intent则是像个小女子含蓄很多，它并不会指出启动哪一个activity，而是指定一系列更多抽象的action和categroy等信息，交给系统去分析这个intent，匹配出合适的activity去启动

使用隐式intent步骤就是先在xml中定义好action和category（在哪个activity下定义就是哪个activity能够响应的），然后使用intent的第二种构造参数，下面是一个例子：

<activity android:name=".MainActivity2"
            android:exported="true">
            <intent-filter>
                <action android:name="com.example.MainActivity2.ACTION_START" />
                <category android:name="android.intent.category.DEFAULT" />
                <category android:name="com.example.MainActivity2.MY_CATEGORY"/>
            </intent-filter>
</activity>

# Activity的生命周期

# activity栈

android使用任务task来管理activity，一个task就是一组存放在栈里的activity的集合，当我们启动一个新的activity，它就会在返回栈中入栈，处于栈顶位置，当我们使用back健或者finish()销毁一个activity的时候，处于栈顶的activity就会出栈。系统总是会显示处于栈顶的activity给用户

# activity状态

根据activity的生命周期，可以分为4种状态

  • 运行状态：位于栈顶的activity就是运行状态
  • 暂停状态：当一个activity不处于栈顶的位置，但是仍然可见，则进入了暂停状态。只有在内存极低的情况下，系统才会考虑回收这种activity
  • 停止状态：不处于栈顶，并且不可见，则是停止状态。处于停止状态有可能会被回收
  • 销毁状态：从返回栈中移除后则是销毁状态

# activity生存期

  • onCreate()：在activity第一次被创建的时候调用。用来完成初始化，比如加载布局，绑定事件
  • onStart()：会在activity由不可见变为可见的时候调用
  • onResume()：会在activity准备好和用户进行交互的时候调用，此时的activity处于返回栈的栈顶
  • onPause()：会在系统准备去启动或者恢复另一个activity的时候调用。通常用来将一些消耗的cpu的资源释放掉，以及保存一些关键的数据。
  • onStop()：会在activity完全不可见的时候调用。
  • onDestory()：会在activity被销毁之前调用
  • onRestart()：会在activity由停止状态变成运行状态之前调用

除了最后一个方法onRestart()，其他都是两两对应的

因此还可以对activity进行下面三种生存期的划分：

  • 完整生存期：Activity在onCreate()方法和onDestroy()方法之间所经历的就是完整生 存期。一般情况下，一个Activity会在onCreate()方法中完成各种初始化操作，而在 onDestroy()方法中完成释放内存的操作。
  • 可见生存期：Activity在onStart()方法和onStop()方法之间所经历的就是可见生存 期。在可见生存期内，Activity对于用户总是可见的，即便有可能无法和用户进行交互。我 们可以通过这两个方法合理地管理那些对用户可见的资源。
  • 前台生存期：Activity在onResume()方法和onPause()方法之间所经历的就是前台生存 期。在前台生存期内，Activity总是处于运行状态，此时的Activity是可以和用户进行交互 的，我们平时看到和接触最多的就是这个状态下的Activity。

# activity被回收了怎么办

当一个activity进入了停止状态（可见生存期外），那么系统可能会回收。如上面的activity生存周期图一样，此时再次返回到这个activity有两种情况：

  • 没有被回收，调用onRestart()
  • 被回收了，调用onCreate()重新创建

那么这时如果activity中存在临时数据和状态就会被抹掉，怎么办？

其实，activity被回收之前还提供了一个回调方法onSaveInstanceState()，这个方法会携带一个Bundle类型的参数，用户我们存放数据。细心的你一定发现了onCreate()方法也有这个类型参数，只需要提前保存就ok啦

# activity的启动模式

activity一共有四种启动模式，并且通过在AndroidManifest.xml中通过给标签指定 android:launchMode属性来选择启动模式

# standard

这个是activity的默认启动模式，standard模式下，只要启动一个心得activity，就会在返回栈中入栈。有点类似java中的普通对象

# singleTop

当启动activiy时发现返回栈已经是栈顶了，则不再创建activity实例。就好比java中的普通对象在某个特定情况下会引用当前正在使用的对象

# singleTask

确保返回栈中永远只存在一个activity单例，需要注意的是，如果发现已经存在则直接使用该实例， 并把返回栈在这个Activity之上的所有其他Activity统统出栈，类似java中的单例对象

# singleInstance

该模式会新建一个返回栈来管理activity，确保当其他程序和我们的程序可以共享这个activity的实例，类似android中的全局那种

# 随时随地退出程序

这里思路也很简单，只需要一个管理activity的集合，然后再baseActivity中对所有的activity添加公有方法，那便是注入和移除，最后不论在哪只需要调用这个集合中的finishAll()方法即可

object ActivityCollector {
    private val activities = ArrayList<Activity>()
    fun addActivity(activity: Activity) {
        activities.add(activity)
    }
    fun removeActivity(activity: Activity) {
        activities.remove(activity)
    }
    fun finishAll() {
        for (activity in activities) {
            if (!activity.isFinishing) {
                activity.finish()
            }
        }
        activities.clear()
    }
}

layout中写的按钮button都会挤兑到一块，经过查阅资料后发现，用代码标签框起来即可</LinearLayout>，但后面发现一个一个的</LinearLayout>也会挤兑一块。这里我对</LinearLayout>的理解就是，一个比较大的容器，装下button，防止重叠，有点像前端中的div标签。后面发现，可以对</LinearLayout>中的内容进行竖排和横排的排版，因此这里有一个比较好的实现让button全部实现的方法

<LinearLayout android:layout_width="wrap_content" android:layout_height="wrap_content"
        android:orientation="vertical" tools:ignore="MissingConstraints">

    <LinearLayout android:layout_width="wrap_content" android:layout_height="60dp"
        android:orientation="horizontal" tools:ignore="MissingConstraints">
        
    </LinearLayout>

    <LinearLayout android:layout_width="wrap_content" android:layout_height="60dp"
        android:orientation="horizontal" tools:ignore="MissingConstraints">

    </LinearLayout>

</LinearLayout>
