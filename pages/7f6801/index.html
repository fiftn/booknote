Android数据库

android目前的三种数据持久化功能：文件存储、SharedPreferences存储以及数据库存储。

# 文件存储

最基本的数据存储方式，比较适合存储一些简单的文件或二进制数据。

# 存储数据

fun save(inputText: String) {
     try {
         val output = openFileOutput("data", Context.MODE_PRIVATE)
         val writer = BufferedWriter(OutputStreamWriter(output))
         writer.use {
         it.write(inputText)
     }
     } catch (e: IOException) {
     	e.printStackTrace()
     }
}

Conte类中提供给了一个openFileOutput()方法，用于保存数据到文件。第一个参数则是指定文件名，第二个参数则是文件操作的模式，有MODE_PRIVATE和MODE_APPEND两种模式可选，默 认是MODE_PRIVATE，前一个是覆盖，第二个是追加。

openFileOutput()方法返回的是一个FileOutputStream对象，得到这个对象之后就可以 使用Java流的方式将数据写入文件中了。

需要注意的是，这里指定的文件名 不可以包含路径，因为所有的文件都默认存储到/data/data//files/目录 下

再来说说kotlin，这里kotlin有两点优化

  • 使用了kotlin中的内置函数use，它会保证在Lambad表达式中的代码全部执行完后自动奖外层的流关闭，相当于这里的java的finally中的操作
  • 这里其实是不需要try-catch的，kotlin中也没有异常检测机制

# 读取数据

对应的Context类提供了openFileinput()方法来从文件中读取数据，

fun load(): String {
     val content = StringBuilder()
     try {
         val input = openFileInput("data")
         val reader = BufferedReader(InputStreamReader(input))
         reader.use {
         reader.forEachLine {
         content.append(it)
     	}
     }
     } catch (e: IOException) {
         e.printStackTrace()
     }
     return content.toString()
}

# SharedPreferences存储

这种采用都是键值对的方式来存储数据的，并且SharedPreferences还支持多种不同的数据类型存储，比如整形，字符串型等等

如果不看参考教程，那么会想出来吗？

其实，这些都是和对象有关，肯定会有一个sharedPreferences对象，至于从怎么拿到这个对象，就得看安卓给我们提供的api了，对象拿到后就是调用对象的存储和读取的方法，并且一个对象实例应该是对应，一个文件的，那么来验证下吧

# 存储数据到SharedPreferences

  • 使用Context类中的getSharedPreferences()方法：第一个参数指定文件名称，第二个参数则是指定操作模式，这里只有一种默认模式，MODE_PRIVATE这一种模式可选
  • 使用Activity类中的的getPreferences()方法：只有一个参数用来接收操作模式，这个方法会自动将当前的activity的类名作为文件名

SharedPreferences文件都是存放在/data/data//shared_prefs/目录下的

拿到对象后，存储数据只需要三步：

  1. 调用SharedPreferences对象的edit()方法获取一个 SharedPreferences.Editor对象。
  2. 向SharedPreferences.Editor对象中添加数据，比如添加一个布尔型数据就使用 putBoolean()方法，添加一个字符串则使用putString()方法，以此类推。
  3. 调用apply()方法将添加的数据提交，从而完成数据存储操作。
class MainActivity : AppCompatActivity() {
     override fun onCreate(savedInstanceState: Bundle?) {
     super.onCreate(savedInstanceState)
     setContentView(R.layout.activity_main)
     saveButton.setOnClickListener {
         val editor = getSharedPreferences("data", Context.MODE_PRIVATE).edit()
         editor.putString("name", "Tom")
         editor.putInt("age", 28)
         editor.putBoolean("married", false)
         editor.apply()
         }
     }
}

# 创建数据库

创建数据库主要是需要用到SQLiteOpenHelper类，并且其实一个抽象类，也就是说我们还需要自己写一个类似的工具类去继承并且使用

为什么道SQLiteOpenHelper需要定义为抽象类?

这其实是更好的设封装，如果是普通类的话，我们可以直接拿来使用。但是创建数据库是需要sql代码的，并且后续的插入表等等一系列sql代码。因此，这里使用抽象类将其封装到我们的继承工具类中，方便我们后续更好的操作

写好自己的继承工具类后，将创建表的sql写在其中，然后拿到工具类的实例，最后通过getReadableDatabase()和 getWritableDatabase()这两个方法写入数据或者读取数据

# 升级数据库最佳写法

思考下为什么前面更改了版本就会执行onUpgrade()方法？

每一个数据库版本都会对应一个版 本号，当指定的数据库版本号大于当前数据库版本号的时候，就会进入onUpgrade()方法中执 行更新操作。这里需要为每一个版本号赋予其所对应的数据库变动，然后在onUpgrade()方法 中对当前数据库的版本号进行判断，再执行相应的改变就可以了

那么针对之前方法，可以做出如下修改：onCreate()中我不动，之前在onUpgrade()为什么需要删除数据库？那是因为如果有之前版本1的用户已经存在了table表，他们的onCreate()便不会执行，因此很简单，只需要在onUpgrade()中指定原先的用户，做一个新建table即可，见如下代码：

class MyDatabaseHelper(val context: Context, name: String, version: Int):
     SQLiteOpenHelper(context, name, null, version) {
         private val createBook = "create table Book (" +
         " id integer primary key autoincrement," +
         "author text," +
         "price real," +
         "pages integer," +
         "name text)"
         private val createCategory = "create table Category (" +
         "id integer primary key autoincrement," +
         "category_name text," +
         "category_code integer)"
         override fun onCreate(db: SQLiteDatabase) {
             db.execSQL(createBook)
             db.execSQL(createCategory)
         }
         override fun onUpgrade(db: SQLiteDatabase, oldVersion: Int, newVersion: Int) {
         if (oldVersion <= 1) {
             db.execSQL(createCategory)
         }
     }
}
