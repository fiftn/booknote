精简动画集合方案学习

所谓的精简动画其实是一个集合，这里我们主要学习一下其背景、目的、方案实现、优化对比、调试方法、宏控等内容

# 背景

针对G99以下项目，使用精简版动画，天玑5G系列平台使用完整版动画，我们在关键场景搭配提频绑核的方式，提升整机的体验，本文将目前覆盖到的所有场景进行整理，方便后续移植，并持续拓展场景。

常见平台性能整理：

X6711 D810 104188 120Hz

由此可见，精简动画只会在一些低端的平台上，因为对于这些平台在负载情况下，复杂的动画会引起卡顿和耗时，影响用户体验，这时我们就需要以用户体验为准，及时切换动画

# 解锁动画

之前的解锁动画，在中低端存在动画抖动的情况，而直接原因，是Launcher动画丢帧引起的，在这个场景中，Launcher会出现绘制超时、binder阻塞、动画资源获取不足等情况，在负载时经常出现卡顿现象

精简版动画使用系统过渡，通过整体缩放的方式简化动画效果，提升绘制效率，并通过SF绑大核的方式提升动画性能。

宏控仓库： TRAN_CODE/device/tran/product
宏控: 
禁用Launcher动画：TSSI_TRAN_LAUNCHER_UNLOCK_ANIM_DISABLE = yes
ro.transsion_disable_launcher_unlock_support = 1
开启精简动画（Go项目仅禁用Launcher动画即可）：TSSI_TRAN_LAUNCHER_UNLOCK_LITE_ANIM_SUPPORT = yes
ro.transsion_enable_lite_launcher_unlock_support = 1

# 应用启动退出场景

应用启动退出过程中，如果动画时间较长，动画比较复杂，在中低端机器上容易出现动画抖动的现象，并且Launcher的RemoteAnimation动画耗费的资源较多，容易引起卡顿问题。

基于此，精简动画关闭了Launcher的Remote动画，全部使用系统动画，其所有实现都在Launcher apk中，系统无需修改。

使用方法
宏控仓库：TRAN_CODE/device/tran/product
宏控（开启后是禁用remote动画）：TSSI_TRAN_LAUNCHER_ANIM_SUPPORT = yes
prop值：ro.transsion_remote_anim_support = 1

# Activity切换场景

测试反馈设置进入二级菜单时动画抖动，经过分析发现此动画使用的是系统转场动画，动画本身不存在性能瓶颈，但从实际体验来看，动画的尾部会有轻微的抖动现象。

针对该现象，我们通过调整动画时长和插值器的方式，来改善这种现象。动画时长从400ms改为了300ms，插值器修改为更加平缓的效果。

宏控仓库：TRAN_CODE/device/tran/product
宏控：OS_LITE_ACTIVITY_ANIMATION_SUPPROT = true
patch链接：https://gerrit-os.transsion.com/c/OST/vendor/tran_os/overlay/+/460484
关键流程：通过overlay的方式替换原生资源

# 绑核提频场景

在日常使用过程中，有些重点的场景，经常遇到卡顿的问题，特别是在负载的情况下，很容易出现资源不足造成卡顿，影响体验。我们为此构建了一套UX Boost方案，在识别到处于关键场景时，主动提升CPU频率，并将动效相关的线程摆到满足性能的CPU上运行，从而提升整体的使用体验。基于对场景的精准把控，此项提升并不影响功耗的表现。

宏控仓库：TRAN_CODE/device/tran/product
宏控：TSSI_TRAN_SCHED_BOOST_GROUP = yes

//android.app.ActivityTaskManager

//场景4表示SF绑大核
public static final int BOOST_SCENE_4 = 4;

//场景6表示SF绑大核，同时Launcher主线程绑大核
public static final int BOOST_SCENE_6 = 6;

//开始boost，参数为上述的场景，需要跟end函数闭合
public void boostSceneStart(int scene) {
    try {
        getService().boostSceneStart(scene);
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}
//开始boost并添加持续时间，此方法适用于没有明确结束点的绑核，比如广播的绑核
public void boostSceneStartDuration(int scene, long durationMs) {
    try {
        getService().boostSceneStartDuration(scene, durationMs);
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}
//结束boost，根据场景结束对应的绑核，这里我们做了各种异常的规避，比如出现了6446的情况
//场景4结束时并不会解除SF的绑核，需要等待6结束后才真正结束，如果出现了4664的情况，
//场景6结束时只会解除Launcher的绑核，不会影响SF的绑核
public void boostSceneEnd(int scene) {
    try {
        getService().boostSceneEnd(scene);
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}
//延迟结束，这里适用于一些需要延迟退出绑核的场景，比如点击后，仍需要一段时间绑核
public void boostSceneEndDelay(int scene, long delayMs) {
    try {
        getService().boostSceneEndDelay(scene, delayMs);
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}

//专门针对Launcher设置的接口，用在SBE方案中，针对Launcher各种滑动场景进行提频绑核
public void boostStartForLauncher(){
    try {
        getService().boostStartForLauncher();
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}
//专门针对Launcher设置的接口，用在SBE方案中，针对Launcher各种滑动场景进行提频绑核
public void boostEndForLauncher(){
    try {
        getService().boostEndForLauncher();
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}

//com.android.server.am.ActivityManagerService#broadcastIntentWithFeature
public final int broadcastIntentWithFeature(IApplicationThread caller, String callingFeatureId,

# Launcher滑动场景

在一些特定的场景下，比如小窗模式、单手模式、G99平台的护眼模式下，此时所有的buffer都会交给GPU合成，而GPU合成的效率不高，会导致性能容易出现瓶颈，而Launcher的桌面滑动、A-Z界面滑动、近期任务列表滑动等场景，对基础体验的影响较大，所以我们在SBE功能中，针对Launcher滑动做了特殊处理，提升其在特殊场景下的体验。

//com.mediatek.boostfwk.identify.scroll.ScrollIdentify

private void inputEventCheck(int status, MotionEvent motionEvent) {
    boolean begin = boostBeginEndCheck(status);
    if (begin) {
        //only copy event when hint begin
        //incase application modify event type
        mCurrentMotionEvent = motionEvent.copy();
        if (motionEvent.getActionMasked() == MotionEvent.ACTION_DOWN) {
            mIsUserTouched = true;
        }
    } else {
        //if event type changed to ACTION_CANCEL by application,
        //use mCurrentMotionEvent we saved at begin.
        MotionEvent event = motionEvent;
        int action = event.getActionMasked();
        if (mCurrentMotionEvent != null) {
            int actionCur = mCurrentMotionEvent.getActionMasked();
            if (action != actionCur && action == MotionEvent.ACTION_CANCEL) {
                event = mCurrentMotionEvent;
                action = actionCur;
            }
        }
        switch (action) {
            case MotionEvent.ACTION_DOWN:
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308 start
                if (TRAN_LAUNCHER_BOOST_SCENE_SUPPORT && ActivityInfo.LAUNCHER_PACKAGE.contains(mDispatcherPkgName)){
                    try {
                        ActivityTaskManager.getService().boostStartForLauncher();
                    } catch (Exception e) {
                        LogUtil.mLoge(TAG, "boost fling failed");
                    }
                }
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308end
                mLastScrollerEnd = false;
                if (mIsScrollLockAcquired && scrollerLock != null) {
                    //force reset scroller flags, when action down,
                    //incase scroller timing issue lead to no ctrl
                    scrollerLock = null;
                    mIsScrollLockAcquired = false;
                }
                mIsUserTouched = true;
                break;
            case MotionEvent.ACTION_UP:
            case MotionEvent.ACTION_CANCEL:
                if (Config.isBoostFwkLogEnable()) {
                    LogUtil.mLogd(TAG, "touch up/cancel ");
                }
                if (mHaveMoveEvent){
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308 start
                    if (TRAN_LAUNCHER_BOOST_SCENE_SUPPORT && ActivityInfo.LAUNCHER_PACKAGE.contains(mDispatcherPkgName)){
                        try {
                            ActivityTaskManager.getService().boostEndForLauncher();
                        } catch (Exception e) {
                            LogUtil.mLoge(TAG, "boost fling failed");
                        }
                    }
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308 end
                    mHaveMoveEvent = false;
                    sbeHint(ScrollPolicy.sFINGER_UP, "Boost when up/cancel " + action);
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308 start
                }else {
                    if (TRAN_LAUNCHER_BOOST_SCENE_SUPPORT && ActivityInfo.LAUNCHER_PACKAGE.contains(mDispatcherPkgName)){
                        try {
                            ActivityTaskManager.getService().boostSceneEnd(ActivityTaskManager.BOOST_SCENE_4);
                        } catch (Exception e) {
                            LogUtil.mLoge(TAG, "boost fling failed");
                        }
                    }
                }
                //T-HUB Core[SPD]:add for boost in launcher by junjie.mou 20230308 end
                mIsInputLockAcquired = false;
                ScrollingFramePrefetcher.getInstance().disableAndLockSFP(false);
                break;
            default:
                break;
        }
}

# Launcher文件夹动画场景

在桌面点击Launcher的文件夹时，经常遇到降频的情况，CPU的调度算法没有很好的保证此场景的需求，导致卡顿，靠着提频绑核框架，我们针对Launcher需要特殊提频的场景，开发了一套接口专供Launcher使用，以提升Launcher的体验。

object CpuBoostController {

    private const val SCENE_ZERO_SCREEN = 0
    private const val SCENE_NORMAL = 1
    private const val SCENE_SPECIAL = 2
    private const val TAG = "CpuBoostController"
    private val sWorkerThread = HandlerThread("cpu-booster").apply { start() }
    private val sWorkerHandler = Handler(sWorkerThread.looper)

    /**
     * 针对负一屏场景，只提升Launcher和负一屏两个进程的优先级，不绑核
     */
    fun boostStartForZeroScreen() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        XLog.d("$TAG boostStartForZeroScreen()")
        FrameworkInvoke.boostSceneStart(SCENE_ZERO_SCREEN)
    }

    fun boostEndForZeroScreen() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        XLog.d("$TAG boostEndForZeroScreen()")
        FrameworkInvoke.boostSceneEnd(SCENE_ZERO_SCREEN)
    }

    /**
     * 针对Launcher ui线程提升优先级和绑大核，并提升对端binder优先级，
     * 适用于负载时runnable过多引起的卡顿问题
     */
    fun boostStartForNormal() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        FrameworkInvoke.boostSceneStart(SCENE_NORMAL)
    }

    fun boostEndForNormal() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        FrameworkInvoke.boostSceneEnd(SCENE_NORMAL)
    }

    /**
     * 针对特殊场景下卡顿问题，例如：单手模式、小窗模式等，
     * 在Normal的基础上提升SurfaceFlinger消费buffer的能力，
     * 适用于单手模式、小窗模式下卡顿的场景。
     * TODO 目前在系统实现该功能，后续优化后使用
     */
    fun boostStartForSpecial() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        XLog.d("$TAG boostStartForSpecial()")
        sWorkerHandler.post { FrameworkInvoke.boostSceneStart(SCENE_SPECIAL) }
    }

    fun boostEndForSpecial() {
        if (!FeatureConfig.TRAN_LAUNCHER_BOOST_SCENE_SUPPORT) {
            return
        }
        XLog.d("$TAG boostEndForSpecial()")
        sWorkerHandler.post { FrameworkInvoke.boostSceneEnd(SCENE_SPECIAL) }
    }
}

# 桌面进入负一屏场景

负载的情况下，长时间静置后第一次从桌面进入负一屏，大概率有卡顿问题，经过分析发现负一屏存在很多的Runnable情况，获取不到CPU资源，但桌面和负一屏的优先级都是正常的，只是在负载情况下无法获取到足够的资源。针对此类问题，我们针对桌面进入负一屏的这个场景，针对Launcher和负一屏提升进程优先级，使其获取CPU资源的能力增强，从而解决卡顿问题。

使用接口：boostStartForZeroScreen()

private void goToOverviewOrHomeOnDragEnd(float velocity) {
    if (goToHomeInsteadOfOverview) {
        if (SUPPORT_PAUSE) {
            //SPD: add for boost in launcher by song.tang 20230403 start
            CpuBoostController.INSTANCE.boostStartForNormal();
            //SPD: add for boost in launcher by song.tang 20230403 end
            mRecentsView.animate()
                    .translationX(exitEndTranslateX)
                    .setInterpolator(TRANSSION_RECENT_OUT_IN)
                    .setDuration(duration)
                    .withEndAction(
                                //SPD: add for boost in launcher by song.tang 20230403 start
                                CpuBoostController.INSTANCE.boostEndForNormal();
                                //SPD: add for boost in launcher by song.tang 20230403 end
                            });
        } else {
            new OverviewToHomeAnim(mLauncher, () -> onSwipeInteractionCompleted(NORMAL))
                    .animateWithVelocity(velocity);
        }

    }
    XLog.d("mReachedOverview = " + mReachedOverview + " goToHomeInsteadOfOverview = " + goToHomeInsteadOfOverview);
    if (mReachedOverview && !(SUPPORT_PAUSE && goToHomeInsteadOfOverview)) {
        //SPD: add for boost in launcher by song.tang 20230403 start
        CpuBoostController.INSTANCE.boostStartForNormal();
        //SPD: add for boost in launcher by song.tang 20230403 end
        mRecentsView.animate()
                .translationX(0)
                .translationY(0)
                //OS: mod add OSTDEV-4113 guisheng.wang5 start
                .setInterpolator(TRANSSION_RECENT_OUT_IN2)
                //OS: mod add OSTDEV-4113 guisheng.wang5 end
                .setDuration(duration)
                .withEndAction(goToHomeInsteadOfOverview
                        ? this::maybeCancelSwipeInteractionToOverview
                        //SPD: add for boost in launcher by song.tang 20230403 start
                        : () -> {
                              maybeSwipeInteractionToOverviewComplete();
                              CpuBoostController.INSTANCE.boostEndForNormal();
                           }
                        //SPD: add for boost in launcher by song.tang 20230403 end
                );
    }
}
