# 查看桢间隔，输出滑动曲线，判断是否丢帧
# 本质上是SBE中打出来了滑动的距离，根据每一帧来的
# 原始数据：OverScroller update, distance = 4506
SELECT REPLACE(name, 'OverScroller update, distance = ', '') AS new_name FROM slice WHERE name LIKE '%OverScroller update, distance = %';

# 这里还有transsion内部的加的启动退出动画距离：
# RectFSpringAnim#onUpdate#progress#0.0#mCurrentRect#RectF(0.0, 0.0, 1224.0, 2720.0002)
# progress是动画进度，RectF是窗口坐标
SELECT 
  SUBSTR(
    name, 
    INSTR(name, 'progress#') + LENGTH('progress#'),
    INSTR(SUBSTR(name, INSTR(name, 'progress#') + LENGTH('progress#')), '#') - 1
  ) AS progress_value
FROM slice
WHERE name LIKE '%progress#%';

    # 用户行为日志

    WindowManager (wm) 相关日志

    用途：记录窗口、Activity 生命周期、焦点变化等

    日志 Key 触发场景 用户行为关联
    wm_on_create_called Activity 的 onCreate() 被调用 用户打开新页面
    wm_on_start_called Activity 的 onStart() 被调用 页面可见（如从后台回到前台）
    wm_on_resume_called Activity 的 onResume() 被调用 页面进入前台并获取焦点
    wm_on_pause_called Activity 的 onPause() 被调用 页面失去焦点（如跳转到其他页面）
    wm_on_stop_called Activity 的 onStop() 被调用 页面不可见（被其他页面覆盖）
    wm_on_destroy_called Activity 的 onDestroy() 被调用 页面被销毁（用户退出或系统回收）
    wm_on_top_resumed_gained_called 当前 Activity 成为顶部并获取焦点（用户切换回应用或新 Activity 启动） 用户与应用交互的前置条件
    wm_task_created 新任务栈被创建（例如通过 Intent.FLAG_ACTIVITY_NEW_TASK 启动 Activity） 用户启动新任务（如从通知栏打开应用）
    wm_task_moved_to_front 任务栈被移到前台（用户点击最近任务列表中的应用） 用户切换应用

    ActivityManager (am) 相关日志 用途：记录 Activity 启动、服务绑定、广播等系统级行为。

    日志 Key 触发场景 用户行为关联
    am_create_activity 系统尝试创建 Activity（解析 Intent 并初始化） 用户触发页面跳转
    am_start_activity 启动一个 Activity（包括跨应用启动） 用户点击链接/按钮跳转
    am_pause_activity Activity 进入 onPause() 状态 用户离开当前页面
    am_resume_activity Activity 进入 onResume() 状态 用户返回页面或新页面加载完成
    am_finish_activity Activity 被主动销毁（用户按返回键或调用 finish()） 用户退出页面
    am_bind_service 绑定到一个 Service（例如音乐播放器后台服务） 用户触发需要后台服务的操作
    am_broadcast_intent 发送广播（例如通知其他组件数据更新） 用户操作触发数据同步

    Input 事件相关日志 用途：记录触摸、按键、手势等输入事件。

    日志 Key 触发场景 用户行为关联
    InputDispatcher: notifyKey 物理按键事件（如返回键、电源键） 用户按下/释放按键
    InputDispatcher: notifyMotion 触摸屏幕事件（包含坐标 x,y） 用户点击、滑动操作
    ViewRootImpl: Process input 应用处理输入事件（如点击按钮） 用户与控件交互
    AccessibilityService: onClick 无障碍服务捕获的控件点击事件（需开启辅助功能） 用户点击特定按钮/视图

    View 系统相关日志 用途：记录视图绘制、布局、触摸事件处理

    日志 Key 触发场景 用户行为关联
    viewroot_draw_event 视图完成绘制（如 VRI[CustomTabActivity],reportDrawFinished） 页面渲染完成（用户可见）
    ViewRootImpl: Touch Event 处理触摸事件的分发（如 ACTION_DOWN, ACTION_UP） 用户点击屏幕
    VRI[ViewName]: layout 视图布局变化（如列表滑动后重新布局） 用户滚动列表

    # 电池相关显示日志信息

    kernel log下：关键字healthd

    <12>[82730.488337]  (6)[822:health@2.1-serv]healthd: battery l=3 v=3665 t=24.8 h=2 st=3 c=-122000 fc=3860000 cc=1 chg=
    1
    • battery l：电池电量，100的时候需要关注st状态，因为可能会出现满电停充
    • v：电池电压
    • t：电池温度
    • h：电池健康状态，一般不用管
    • st：实时状态，如下：（1-Unknow ；2-charging ；3-discharging；4-not_charging插着充电器没充电；5-full）
    • c：实时的库伦值，可以看到当前的电流情况，简单可以理解为c = 进电池电流 - 系统耗流
    • fc：full charge，满电容量，随着电池使用，这个数值会降低，和电池老化有关
    • cc：cycle count，表示循环次数，充满再放完算一个充放周期，和电池老化有关
    • chg：充电类型，u表示usb，a表示墙充

    其中一行日志解读

    • Line 13695: 这是日志中的行号，用于快速定位和调试问题。
    • 07-31 18:51:06.314921: 这是记录的时间戳，表示日志的生成时间，格式为月-日 小时:分钟:秒.毫秒。
    • 1571 5617: 这是进程的PID（Process ID）和TID（Thread ID），用于标识唯一的进程和线程。
    • I AnrManager: 这是日志级别和标签。在这种情况下，I表示信息级别（Information），AnrManager是日志的标签，用于标识日志的来源。
    • 91% TOTAL: 53% user + 26% kernel + 11% iowait + 0.4% softirq: 这部分是有关系统性能的信息。它表示系统的CPU利用率统计，以百分比的形式呈现。具体含义如下：
    • TOTAL: 总的CPU利用率为91%。
    • user: 用户空间的CPU利用率为53%。这是由用户进程使用的CPU时间。
    • kernel: 内核空间的CPU利用率为26%。这是由内核进程使用的CPU时间。
    • iowait: CPU等待I/O操作完成的时间的占比为11%。这主要涉及磁盘读写等I/O操作。
    • softirq: 软中断的CPU利用率为0.4%。软中断是一种由内核发起的异步事件处理机制。
