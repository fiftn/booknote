vscode远程连接云服务器调试内核

学习内核，光看是不行的，需要动手去调试代码，才能更好的理解。但是windows上装虚拟机太麻烦，并且公司电脑也不允许装虚拟机，于是这里我想到直接远程调试开发云服务器，学习内核。

# 基础知识

调试内核，首先就需要我们能够修改内核，并且编译内核，得到内核的镜像，然后制作文件系统，因为没有文件系统，内核是无法运行的！

内核的编译使用的基本是GCC编译器，因为内核里的大部分代码也都是C写的。关于GCC的编译，

为什么c文件通过gcc编译 ，得到可执行的二进制文件。 但是内核通过gcc编译就是 一个内核image映像？

这是因为 C 文件和 Linux 内核是不同的类型和用途，所以它们在编译和生成可执行文件方面存在差异。当您使用 GCC 编译单个 C 文件时，GCC 会将其编译为一个独立的可执行程序。这个可执行文件可以包含主函数和相关的函数定义，可以在计算机上直接运行。然而，Linux 内核是一个庞大的软件项目，由许多源文件组成，其中包括驱动程序、系统调用、网络协议栈等等。GCC 编译器将这些源代码文件编译成一个内核映像（通常称为 vmlinuz），它是一个压缩的二进制文件，包含了整个内核的代码和数据。内核映像不是可执行程序，而是操作系统的一部分。它被加载到计算机的内存中，并由引导程序（比如 GRUB）负责启动。内核映像是与硬件交互的核心组件，提供了操作系统的基本功能和服务。因此，C 文件和内核在编译和生成可执行文件方面的差异是由于它们的不同用途和执行环境所决定的。C 文件通常被编译为独立的可执行程序，而内核源代码则被编译为一个整体的内核映像，以支持操作系统的启动和运行。

这就是编译的目的！

那么我们就需要下载一套内核源码，这里我推荐区清华开源站下载 linux-stable 稳定版，并且可以根据git 切换到任意的稳定版本，十分方便！

当然，我们还需要调试内核，这个就要和硬件打交道，cpu的架构有很多种，因此，内核也有不同的架构，我们可以使用一个模拟软件qemu，来调试参数，运行在我们想要的虚拟的硬件上

此外，调试我们需要开启一些内核的调参开关，并且安装GDB，这个是各种语言的调试程序，可以自行百度了解。

最后，就是连接上vscode来更方便的修改内核源码，以及进行调试内核。

配置选项：

  • Initial RAM filesystem and RAM disk (initramfs/initrd) support：

意义：支持初始 RAM 文件系统和 RAM 磁盘（initramfs/initrd），这对于在启动时加载内核模块非常重要。 调试需求：如果需要在内核启动时加载自定义模块或文件系统，必须启用此选项。

  • RAM block device support：

意义：支持 RAM 块设备，使系统能够使用 RAM 作为块设备。 调试需求：常用于模拟磁盘设备或测试块设备的性能，必须启用。

  • Compile the kernel with debug info：

意义：在编译内核时包含调试信息。 调试需求：对于调试内核，必须启用此选项，以便可以使用 GDB 进行源码级别调试。

  • Provide GDB scripts for kernel debugging：

意义：提供用于内核调试的 GDB 脚本。 调试需求：对于使用 GDB 调试内核，必须启用此选项。

  • Processor type and features ----> [] Randomize the address of the kernel image (KASLR) 关闭KASLR，否则会导致打断点失败,KASLR会随机化内核的地址空间， 开始编译

# 配置vscode进行内核调试

官方vscode配置含义参考 (opens new window)

行动 解释

继续/暂停 F5 继续：恢复正常的程序/脚本执行（直到下一个断点）。暂停：检查当前行执行的代码并逐行调试。

跨过 F10 将下一个方法作为单个命令执行，而不检查或遵循其组成步骤。

进入 F11 输入下一个方法来逐行跟踪其执行。

步出 Shift+F11 在方法或子例程内部时，通过完成当前方法的剩余行返回到先前的执行上下文，就像它是单个命令一样。

重新启动 Ctrl+Shift+F5 终止当前程序执行并使用当前运行配置再次开始调试。

停止 Shift+F5 终止当前程序的执行。

直接运行 ctrl+F5 运行（启动而不调试）程序

设置断点 F9
