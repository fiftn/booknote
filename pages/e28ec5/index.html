进程管理

# 概念

# 进程和线程的定义

进程：操作系统资源分配的基本单位。

线程：操作系统调度的基本单位。

# 进程和线程的通信方式

# 进程通信方式
  1. 匿名管道( pipe )：管道是一种半双工的通信方式，数据只能单向流动，而且只能在具 有亲缘关系的进程间使用。进程的亲缘关系通常是指父子进程关系。
  2. 有名管道 (named pipe) ： 有名管道也是半双工的通信方式，但是它允许无亲缘关系 进程间的通信。
  3. 信号量( semophore ) ： 信号量是一个计数器，可以用来控制多个进程对共享资源的 访问。它常作为一种锁机制，防止某进程正在访问共享资源时，其他进程也访问该资源。 因此，主要作为进程间以及同一进程内不同线程之间的同步手段。
  4. 消息队列( message queue ) ： 消息队列是由消息的链表，存放在内核中并由消息队 列标识符标识。消息队列克服了信号传递信息少、管道只能承载无格式字节流以及缓冲 区大小受限等缺点。
  5. 信号 ( sinal ) ： 信号是一种比较复杂的通信方式，用于通知接收进程某个事件已经 发生。
  6. 共享内存( shared memory ) ：共享内存就是映射一段能被其他进程所访问的内存，这 段共享内存由一个进程创建，但多个进程都可以访问。共享内存是最快的 IPC 方式， 它是针对其他进程间通信方式运行效率低而专门设计的。它往往与其他通信机制，如信 号两，配合使用，来实现进程间的同步和通信。
  7. 套接字( socket ) ： 套解口也是一种进程间通信机制，与其他通信机制不同的是，它 可用于不同及其间的进程通信。
# 线程通信方式
  1. 锁机制：包括互斥锁、条件变量、读写锁 互斥锁提供了以排他方式防止数据结构被并发修改的方法。 读写锁允许多个线程同时读共享数据，而对写操作是互斥的。 条件变量可以以原子的方式阻塞进程，直到某个特定条件为真为止。对条件的测试是在 互斥锁的保护下进行的。条件变量始终与互斥锁一起使用。
  2. 信号量机制(Semaphore)：包括无名线程信号量和命名线程信号量
  3. 信号机制(Signal)：类似进程间的信号处理 线程间的通信目的主要是用于线程同步，所以线程没有像进程通信中的用于数据交换的 通信机制。

# 段错误

段错误（Segmentation fault）是一种常见的程序运行错误，指的是程序尝试访问一个未分配给它的内存段或者访问已经释放的内存段。当程序发生段错误时，操作系统会中断运行并终止该程序的执行。

常见导致段错误的情况包括：

  • 解引用空指针：当程序试图使用空指针访问内存时，操作系统会检测到该非法访问并引发段错误。
  • 访问越界：当程序使用数组或指针访问超过其分配长度或索引范围的内存时，会导致段错误。
  • 使用已释放内存：当程序通过已经释放的指针或指向已释放的对象进行访问时，会引发段错误。
  • 栈溢出：当程序的递归调用或者局部变量过多导致函数调用栈超过了系统允许的最大深度时，会发生栈溢出，导致段错误。
  • 非法的指针操作：例如对函数指针执行错误的调用，或者进行非法的指针运算，都可能导致段错误。

段错误通常是由于编程错误导致的，如访问未初始化的变量、错误的内存分配或释放、指针操作错误等。当程序发生段错误时，通常需要进行调试和修复代码，以确保内存的正确访问和处理。调试工具和技术（如使用调试器、编译器选项等）可以帮助定位和解决产生段错误的问题。

动态链接库和静态链接库区别：

  • 静态链接库：一旦发生链接，代码合变量的section都会被合并，
    • 好处：程序运行时，不必依赖这个库是否存在
    • 坏处：多个程序运行时，内存中就会存在多份，浪费资源；并且库一旦更新，所有程序的二进制文件都需要重新更新链接
  • 动态链接库：一旦发生链接，代码不会合并，仅仅报错对动态链接库的引用，并且只保存名称，因为系统只会在/lib 合/usr/lib文件夹下寻找动态链接库；当然，我们可以设定LD_LIBRARY_PATH环境变量，指定加载路径。至于动态链接库是如何做到：可以将 so 文件动态链接到进程空间的呢，我没去深究，但需要知道的是动态连接库在进行动态加载的时候，共享库会在链接时不是像静态库那种将其代码和数据复制到可执行文件中；而是运行时动态加载到内存中，并与可执行文件进行链接

由此可见，ELF文件有三种格式：

  • 可重定位文件：也就是.o文件，值得说的是.a文件就是一堆.o文件的集合
  • 共享对象文件：.so文件，可被动态链接到可执行文件里
  • 可执行文件：可以被execve加载的文件

可重定位文件：

这个文件格式在内核中有定义，分别为 struct elf32_hdr 和 struct elf64_hdr

这些节代表的含义分别是：

  • .text：放编译好的二进制可执行代码
  • .data：已经初始化好的全局变量
  • .rodata：只读数据，例如字符串常量、const 的变量
  • .bss：未初始化全局变量，运行时会置 0
  • .symtab：符号表，记录的则是函数和变量
  • .strtab：字符串表、字符串常量和变量名

这里只有全局变量，由此可知，函数里的局部变量是放在函数栈中的；可重定位的含义是表示，.rel.text和.rel.data和可重定位有关系，因为当一个函数调用另一个库函数的时候，另一个库函数还是.o文件，自己并不知道其位置，只能作为可重定位文件标注！如果直接编译，就会报错，编译器不知道你要调用的库函数文件在哪？如何解决？这就是静态链接库或者动态链接库了

# 线程意义

如果一个进程只存在主线程，那么随便思考一下就知道这不行；比如只有一个主线程，当收到其他信号做别的事情，不可能断掉主线程去干

# 线程创建流程

#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
 
#define NUM_OF_TASKS 5
 
void *downloadfile(void *filename)
{
   printf("I am downloading the file %s!\n", (char *)filename);
   sleep(10);
   long downloadtime = rand()%100;
   printf("I finish downloading the file within %d minutes!\n", downloadtime);
   pthread_exit((void *)downloadtime);
}
 
int main(int argc, char *argv[])
{
   char files[NUM_OF_TASKS][20]={"file1.avi","file2.rmvb","file3.mp4","file4.wmv","file5.flv"};
   pthread_t threads[NUM_OF_TASKS];
   int rc;
   int t;
   int downloadtime;
  
   //设置线程属性
   pthread_attr_t thread_attr;
   pthread_attr_init(&thread_attr);
   pthread_attr_setdetachstate(&thread_attr,PTHREAD_CREATE_JOINABLE);
 
   for(t=0;t<NUM_OF_TASKS;t++){
     printf("creating thread %d, please help me to download %s\n", t, files[t]);
     /*
     创建线程函数 pthread_create
     第一个参数，标识线程，传入pthread_t* 类型的指针，主要标识线程几
     第二个参数，指向线程属性的指针，可以设置线程栈的大小，调用策略
     第三个参数：线程要做的事情，函数
     第四个参数，第三个参数中的函数要传入的参数
     */
     rc = pthread_create(&threads[t], &thread_attr, downloadfile, (void *)files[t]);
     if (rc){
       printf("ERROR; return code from pthread_create() is %d\n", rc);
       exit(-1);
     }
   }
  
   pthread_attr_destroy(&thread_attr); //因为线程不再用了，销毁属性对象，释放资源
 
   for(t=0;t<NUM_OF_TASKS;t++){
     pthread_join(threads[t],(void**)&downloadtime); //等待子线程结束，主线程再退出
     printf("Thread %d downloads the file %s in %d minutes.\n",t,files[t],downloadtime);
   }
 
   pthread_exit(NULL);//退出线程
}

# 线程中的数据

在单线程的程序中，有两种基本的数据，全局变量和局部变量 但是在多线程的程序中，还有第三种数据类型：线程私有数据变量

三类数据具体分别是：

  • 线程栈上的本地数据（局部变量）：

线程栈（Stack）是线程的私有空间，用于存储局部变量、函数调用信息等。线程栈中的数据只能被所属线程直接访问和修改，其他线程无法直接访问。这包括局部变量、函数参数、返回地址等信息

进程栈的大小可以使用ulimit -a查看，默认是8mb，还可以使用ulimit -s修改；在创建线程的时候，可以使用pthread_attr_t函数，修改线程栈的大小

段错误：本质上理解，段错误中有一个栈溢出的错误，其实就是：主线程在内存中有一个栈空间，其他线程栈也拥有独立的栈空间。为了避免线程之间的栈空间踩踏，线程栈之间还会有小块区域，用来隔离保护各自的栈空间，一旦另一个线程踏入到这个隔离区，就会引发段错误

  • 线程私有数据：

线程私有数据是每个线程独立拥有的，其他线程无法直接访问和修改。这些数据对于特定线程来说是私有的，可以用于存储线程的状态、上下文信息等。例如，线程ID（Thread ID）、线程状态（State）、寄存器上下文（Register Context）等都属于线程私有数据。

  • 在整个进程里共享的全局数据（全局变量）：

公有数据是多个线程共享的数据，可以被多个线程同时访问和修改。这些数据可以用于线程之间的通信和共享信息，例如线程组ID（Thread Group ID）、全局变量等。对于公有数据的访问需要确保并发访问的正确性和同步性。全局变量也是同步机制的重点

  • CFS Class（完全公平调度器）：用于普通进程，包括 SCHED_NORMAL 和 SCHED_BATCH 调度策略，适用于大多数非实时任务。

  • Idle Class：用于最低优先级的空闲进程，SCHED_IDLE，当系统没有其他任务需要运行时，运行这些任务。它也是用于普通进程，但这些进程的优先级非常低。

  • Realtime Class：用于实时进程，包括 SCHED_FIFO 和 SCHED_RR 调度策略。这些策略适用于需要实时响应的任务。

  • Deadline Class：用于实时进程，采用 SCHED_DEADLINE 调度策略，允许任务指定绝对的截止时间，适用于非常严格的实时任务。

  • Stop Class：用于系统停止任务，这些任务具有最高优先级，用于系统的关键操作，比如停止 CPU。这类任务通常不会直接被用户进程使用。

static void __enqueue_entity(struct cfs_rq *cfs_rq, struct sched_entity *se)
{
	struct rb_node **link = &cfs_rq->tasks_timeline.rb_root.rb_node;
	struct rb_node *parent = NULL;
	struct sched_entity *entry;
	bool leftmost = true;

	/*
	 * Find the right place in the rbtree:
	 */
	while (*link) {
		parent = *link;
		entry = rb_entry(parent, struct sched_entity, run_node);
		/*
		 * We dont care about collisions. Nodes with
		 * the same key stay together.
		 */
		if (entity_before(se, entry)) {
			link = &parent->rb_left;
		} else {
			link = &parent->rb_right;
			leftmost = false;
		}
	}

	rb_link_node(&se->run_node, parent, link);
	rb_insert_color_cached(&se->run_node,
			       &cfs_rq->tasks_timeline, leftmost);
}

可以看到如果判断leftmost为true，直接插入到最左节点，如此看来这个leftmost的意义是：

  • 快速访问最左节点：在调度器中，最左节点（即 vruntime 最小的节点）是优先调度的。通过缓存最左节点，调度器可以快速找到优先级最高的进程，而不需要每次都遍历整棵树。
  • 提高效率：使用 leftmost 参数可以在插入节点时立即判断并更新最左节点，从而避免额外的查找操作，提高调度效率。
