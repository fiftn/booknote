广播！

在网络通信中，比如某个网络的IP范围是192.168.0.XXX，子网掩码是 255.255.255.0，那么这个网络的广播地址就是192.168.0.255。广播数据包会被发送到同一 网络上的所有端口，这样该网络中的每台主机都会收到这条广播。为了便于进行系统级别的消息通知，Android也引入了一套类似的广播消息机制。

# 广播类型

# 标准广播

这是一个完全异步执行的广播，类似mq，在广播发出后，几乎所有的BroadcastReceiver会同时收到这条广播

# 有序广播

这是一个同步执行的广播，同一时间，只有一个BroadcastReceiver可以接收到这个广播，当这个BroadcastReceiver中的逻辑执行完毕后，广播才会继续传递。因此此时的BroadcastReceiver也是有优先级的，并且前面的还可以截断正在传递的广播

# 接收广播

接收广播需要注册BroadcastReceiver，有两种注册方式：在代码中注册和在AndroidManifest.xml中注册，前者为动态注册，后者则是静态注册

# 动态注册

class guangbo : AppCompatActivity() {
    //创建BroadcastReceiver子类实例
    lateinit var timeChangeReceiver: TimeChangeReceiver

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_guangbo)
        //实例对象
        timeChangeReceiver = TimeChangeReceiver()

        //意图过滤器，作为触发器第二参数
        val intentFilter = IntentFilter()
        intentFilter.addAction("android.intent.action.TIME_TICK")

        // 触发器就是需要registerReceiver()，方法传入实例对象，和intentFilter对象
        //也就是对谁触发，触发什么？
        registerReceiver(timeChangeReceiver,intentFilter)

    }

    override fun onDestroy() {
        super.onDestroy()
        //退出页面的时候销毁实例，节省内存
        unregisterReceiver(timeChangeReceiver)
    }

    //需要继承BroadcastReceiver
    inner class TimeChangeReceiver:  BroadcastReceiver(){
        //触发事件
        override fun onReceive(context: Context, intent: Intent) {
            Toast.makeText(context,"现在时间改变了",Toast.LENGTH_SHORT).show()
        }

    }
}

# 静态注册

动态注册可以自由控制与注销很方便，但是有一个缺点就是必须程序启动之后才能接收广播，因为注册的逻辑代码是在onCreate()方法中写的。这时就需要静态注册了。

理论上，静动态注册是一样的，但是后面由于静态注册开放，导致大量恶意app利用这个机制，严重影响手机性能，因此后续中大多数系统广播都不允许静态注册了

静态注册也很简单，这里新建BroadcastReceiver组件可以直接使用快捷键包→New→Other→Broadcast Receiver，并且会自动注册到AndroidManifest.xml中去，两件事，类中写触发事件，xml中写触发器

class guangbo2 : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        // This method is called when the BroadcastReceiver is receiving an Intent broadcast.
        Toast.makeText(context, "叮咚，开机啦", Toast.LENGTH_LONG).show()
    }
}

# 发送标准广播

贼简单，发就完事了

button.setOnClickListener {
     val intent = Intent("com.example.broadcasttest.MY_BROADCAST")
     intent.setPackage(packageName)
     sendBroadcast(intent)
 }

这里用按钮作为触发器，后续接收的话，则是intentFilter.addAction("com.example.broadcasttest.MY_BROADCAST")，这里的intent.setPackage(packageName)则是指定这个广播是发送给哪个应用程序的，从而让它变成一条显式广播，否则静态注册的BroadcastReceiver将 无法接收到这条广播。

# 发送有序广播

有序广播的发送只需要改动一行代码，如下：

button.setOnClickListener {
     val intent = Intent("com.example.broadcasttest.MY_BROADCAST")
     intent.setPackage(packageName)
     sendOrderedBroadcast(intent, null)
}
1
2
3
4
5

即将sendBroadcast()方法改成 sendOrderedBroadcast()方法。sendOrderedBroadcast()方法接收两个参数：第一个 参数仍然是Intent；第二个参数是一个与权限相关的字符串，这里传入null就行了。

值得注意的是，有序广播是具有优先级的，但是这和发送没关系，优先级的定义在接收的BroadcastReceiver的注册时候设定，在xml中的设定如下：

<intent-filter android:priority="100">
 	<action android:name="com.example.broadcasttest.MY_BROADCAST"/>
</intent-filter>
