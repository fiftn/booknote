Swap 相关属性
persist.vendor.swapfile_enable: [true]
这表明系统启用了交换文件。交换文件是硬盘上的一个特定区域，用于当物理内存不足时，临时存储内存中的数据。

persist.vendor.swapfile_size_mb: [5120]
这表示系统配置的交换文件大小为 5120MB。更大的交换文件可以在内存压力较大时提供更多的虚拟内存，但如果频繁使用，可能会影响闪存存储的寿命和系统性能。

ro.lmk.swap_free_low_percentage: [15]
这是低内存杀手（Low Memory Killer, LMK）的一个参数，表示当空闲的交换空间低于总交换空间的 15% 时，系统会开始清理任务以释放内存。

ro.lmk.swap_util_max: [90]
这个参数表示系统最多可以使用交换空间的 90%，超过这个比例时，LMK 会更积极地杀死进程以释放内存。

ro.vendor.mtk_sim_hot_swap_common_slot: [1]
这个参数与内存或交换空间无关，而是指 SIM 卡的热插拔功能。

/proc/sys/vm/swappiness: [100]
这个值定义了内核倾向于使用 swap 空间的程度。值范围从 0 到 100，值越高，内核越倾向于使用交换空间。值为 100 表示内核会非常积极地使用交换空间，即使有足够的物理内存空间。

ZRAM 相关命令
/sys/block/zram0/disksize
显示了 ZRAM 设备的总大小，这个大小是动态配置的，通常根据系统的总内存大小的一定比例来设置。

/sys/block/zram0/orig_data_size
显示存储在 ZRAM 中的原始数据的大小，即在压缩之前的数据大小。

/sys/block/zram0/compr_data_size
显示存储在 ZRAM 中的数据的压缩后大小。

/sys/block/zram0/mem_used_total
显示 ZRAM 总共使用的内存大小，包括所有管理结构和压缩数据的内存。

内存水位（Watermark）
/proc/sys/vm/watermark_scale_factor: [200]
这个参数调整 kswapd 守护进程的工作敏感度。它影响页面回收逻辑，当内存水位低于某个阈值时，kswapd 会被唤醒来回收页面。watermark_scale_factor 的值越高，系统对内存压力的响应就越敏感。

这个参数/proc/sys/vm/watermark_scale_factor 和ro.lmk.swap_free_low_percentage 有啥关系， kswapd和lmk有啥区别，分别回收哪些内存，作用是啥

这里的ZRAM 大小是指什么空间，和swap有啥区别，作用分别是啥

  • LMK（Low Memory Killer） Low Memory Killer (LMK) 是 Android 系统中一个重要的内存管理机制，专门用于在内存不足时终止进程以释放资源。当系统可用内存降到某个阈值时，LMK 会根据进程的重要性（通常是 oom_score）来决定哪些进程应该被杀死以回收内存。

ro.lmk.swap_free_low_percentage 参数定义了触发 LMK 动作的一个条件，即当可用交换空间低于设置的百分比时，LMK 会开始工作来杀死一些进程，释放内存。这意味着系统在考虑内存回收时，不仅会考虑物理内存的使用情况，还会考虑交换空间的使用情况。

  • Kswapd Kswapd 是 Linux 内核的一个守护进程，负责管理内存中的页面，尤其是在内存不足时将页面从物理内存移动到交换空间（swap）。Kswapd 会在系统内存达到一定的“水位”时被唤醒，以回收页面，减轻内存压力。

/proc/sys/vm/watermark_scale_factor 参数会影响 kswapd 的触发机制。这个参数调整了系统对内存水位的敏感度，影响了 kswapd 被唤醒来回收内存的时机。

  • LMK vs Kswapd 区别与联系： LMK 和 kswapd 都是系统内存管理的一部分，但它们的工作方式和目标不同。Kswapd 专注于通过交换机制管理内存，即将不活跃的页面移动到交换空间。而 LMK 专注于在内存极度紧张时通过杀死进程来快速释放内存。 协作： 在系统内存非常紧张的情况下，kswapd 可能无法通过交换来有效减轻内存压力，这时 LMK 就会介入，通过杀死进程来释放内存。

  • ZRAM vs Swap

ZRAM： ZRAM 提供一种压缩的交换空间，它在内存中创建一个压缩块设备。与传统的基于磁盘的交换空间相比，ZRAM 可以更快地访问数据，因为访问内存速度远高于磁盘。ZRAM 的大小通常是基于物理内存大小的一定比例来设置的。

Swap： 传统的交换空间（Swap）通常位于磁盘上，当物理内存不足时，系统会将内存中的数据页移动到磁盘上的交换区，从而释放物理内存。这个过程的速度较慢，因为磁盘的访问速度远低于内存。

  • 作用与区别： 虽然 ZRAM 和传统的 Swap 都是解决内存不足问题的手段，但 ZRAM 由于其基于内存的特性，提供了更快的数据访问速度，尤其适用于物理内存较小的设备。然而，ZRAM 使用的是压缩存储，所以它在压缩和解压缩数据时会占用一定的 CPU 资源。而传统的 Swap 虽然访问速度慢，但不会占用 CPU 资源进行数据压缩和解压缩。通过协调使用 ZRAM 和传统的 Swap 空间，Android 系统能够更有效地管理内存，尤其是在多任务和内存需求高的情况下。ZRAM 提供了一种高效的方式来扩展物理内存，尤其是在物理内存不足时，而传统 Swap 提供了一种更持久的内存溢出解决方案，尽管其速度较慢。

  • 总结它们的作用：

ZRAM：提供快速的内存扩展方式，适用于内存紧张但需要快速响应的场景。它通过压缩内存中的数据来增加有效的内存容量，但会使用一些 CPU 资源来处理压缩和解压缩操作。

Swap：传统的 Swap 提供一种更稳定的内存扩展方式，适用于长时间运行的应用或系统，但访问速度较慢。它将不常用的数据移动到磁盘上，从而为更需要的数据腾出空间。

LMK：当系统内存达到临界点时，LMK 确保系统稳定性通过终止那些内存使用量大但优先级低的进程。

Kswapd：负责平衡内存使用，通过将不活跃的页面移至交换空间（包括 ZRAM 或传统 Swap），保持系统的流畅运行。

在 Android 系统中，这些组件和机制共同协作，确保了即使在内存受限的情况下，设备也能保持良好的性能和响应速度。了解这些机制对于优化 Android 设备的性能和内存管理是非常有帮助的。
